# PMS 0.4.0 — что изменилось

Дата: 19.11.2026. Релиз собирает два раунда аудита (`docs/reports/2026-11-1[89]-*`): безопасность, производительность, генератор.

## Безопасность

* **Доступ к файловой системе ограничен.** Приложение больше не может читать/писать произвольные пути: доступ выдаётся только через нативный диалог, проверяется по канонизированному пути и наборе разрешённых корней (`commands/fs_scope.rs`). Запоминаются только папки, в которых лежит `pms.vault`.
* **Импорт недоверенных файлов.** Ограничена работа KDF (произведение памяти и итераций) для KeePass/Bitwarden, распаковка zip ограничена бюджетом, JSON-метаданные — отдельным лимитом, keyfile — 1 МиБ до декодирования. `quick-xml` обновлён до патченной версии; исправлена потеря `&amp;` в KeePass-XML.
* **Восстановление архивов** создаёт файлы с правами 0600/0700 и не оставляет «битый» бэкап при изменении файлов во время экспорта.
* **macOS-биометрия** хранит ключ в data-protection keychain с `SecAccessControl`: чтение требует Touch ID или пароля устройства. Если система этого не позволяет (сборка без подписи, нет пароля), приложение честно предупреждает в настройках, что ключ читается без запроса.
* **Передача по локальной сети**: код из 8 символов (~40 бит, ввод без учёта регистра), срок 2 минуты, 3 попытки, HMAC тела запроса.
* **Троттлинг разблокировки**: после 3 неудачных попыток задержка растёт до 5 минут и переживает перезапуск (общая для пароля и биометрии).
* Секреты в моделях зануляются при освобождении; значения в буфере обмена помечаются как «не сохранять в историю» (macOS); загрузка значков сайтов выключена по умолчанию.
* Android: `allowBackup=false` + правила извлечения данных (бэкап устройства не забирает приватные данные).
* CI: `cargo audit`, `cargo deny`, `pnpm audit`, actions прибиты по commit SHA.

## Производительность

* Сохранение шифрует документ в одном буфере: **1.07× размера JSON в пике** вместо 2.66×, две реаллокации вместо девяти.
* Файл хранилища, чтение и вложения больше не ходят через base64; сохранение на desktop пишется сразу в Rust (`vault_save_to`). Сохранение 4 МиБ: ~148 мс → ~14 мс.
* Экспорт/импорт архива потоковый: прирост памяти **0.3 МиБ на 191 МиБ данных**.
* AES-256-GCM на Apple Silicon/ARM Linux: **184 → 905 МиБ/с** (включён ARMv8-бэкенд, выбор — по `cpufeatures` во время выполнения).
* Тяжёлые команды (разблокировка, сохранение, вложения, импорт, архивы) выполняются вне основного потока.
* Фронтенд: виртуальный список записей (5 000 записей → 19 карточек в DOM), кэш значков в IndexedDB, декодирование QR вне главного потока.

## Генератор

* Новый режим **парольной фразы**: список EFF (7776 слов) или **свой словник**, 3–12 слов, 8 разделителей, заглавные буквы, цифра в начале или в конце.
* Типы пароля: **случайный**, **читаемый** (произносимые слоги), **ПИН-код** (4–12 цифр, без `1111`/`1234`).
* Минимальное число цифр и спецсимволов, исключение конкретных символов, пресеты длины, показ энтропии.
* История последних 20 генераций (только на время сессии, очищается при блокировке).
* **Проверка утечек** по клику (HIBP, k-anonymity: наружу уходят только 5 символов SHA-1).
* Слабый результат блокирует «Использовать» с подсказкой, что увеличить.

## Записи

* **Правила пароля сайта** в записи (длина, обязательные наборы, запрещённые символы) — применяются автоматически, если открыть генератор из этой записи.
* **Напоминание о ротации**: в карточке и в детали видно, что пароль не менялся более 180 дней, с кнопкой «сгенерировать новый».

## Тесты и документация

* 215 Rust unit-тестов, интеграционные наборы: `operations` (латентность/RSS), `perf_suite` (аллокации/пики), `parser_robustness` (мутационный фаззинг всех парсеров недоверенных данных).
* 318 фронтенд-тестов, 35 e2e.
* Отчёты: `docs/reports/2026-11-18-*`, `2026-11-19-*` (аудит безопасности и производительности, ревью генератора).

## Известные ограничения

* Touch ID-хранилище и Android-сборка проверены компиляцией и тестами, но требуют прогона на живом устройстве (см. чек-лист в `2026-11-19-security-audit-2.md`).
* Маркировка буфера обмена «не сохранять» реализована для macOS; на Windows/Linux значение копируется обычным способом.
* **Формат хранилища v2**: набор способов разблокировки аутентифицирован (удаление слота без ключа делает файл нерасшифровываемым). Файлы v1 открываются и переводятся в v2 при первой смене пароля или удалении слота — отдельной миграции не нужно.
* `cargo fmt --check` пока не включён в CI: репозиторий был не выровнен до этого релиза (в 0.4.0 форматирование приведено в порядок, проверку можно включать).
