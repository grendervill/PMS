# Банковские карты и документы

Дата: 2026-10-24
Статус: утверждено и реализовано (2026-10-24)

## Зачем

В PMS уже есть логины, TOTP, SSH-ключи и вложения, но нет места для двух
вещей, которые люди постоянно носят с собой: банковских карт и документов.
Нужно хранить их в том же зашифрованном хранилище, показывать карту так, как
она выглядит в кошельке, и давать доступ к CVV/сроку без лишних переходов.

## Что входит

- Новый раздел «Карты» в левом меню.
- Новый раздел «Документы» в левом меню.
- Банковская карта с реалистичным внешним видом, пресетами оформления и
  загрузкой своей картинки.
- Переворот карты в детальном просмотре: срок и CVV на обратной стороне.
- Паспорт РФ / загранпаспорт, СНИЛС и водительское удостоверение.
- Вложения для документов (сканы/фото оригиналов).
- Поиск внутри каждого раздела, редактирование и удаление.
- Синхронизация схемы хранилища с Rust и Android.

## Что не входит

- QR-передача отдельных карт/документов.
- Импорт карт/документов из Bitwarden, 1Password и других менеджеров.
- OCR, распознавание номеров по фото и проверка банковских BIN.
- Напоминания об истечении срока карты или документа.
- Отдельные черновики карт/документов при автоблокировке: форма закроется,
  несохранённые изменения пропадут. Черновики записей остаются как сейчас.
- Брендинг банков/платёжных систем на карте: только пользовательская
  картинка или абстрактный пресет.

## Данные

Новые сущности лежат в расшифрованном `VaultData` рядом с `entries`,
`sshKeys` и `attachments`. Формат зашифрованного файла не меняется; старые
хранилища открываются с пустыми массивами благодаря `serde(default)`.

### Банковская карта

```ts
type CardImagePreset =
  | "emerald"
  | "graphite"
  | "midnight"
  | "oxblood"
  | "sand"
  | "copper";

type BankCard = {
  id: string;
  schemaVersion: number;
  number: string;        // только цифры, 13–19
  expiry: string;        // MM/YY
  cvv: string;           // 3–4 цифры
  holder: string;        // ИМЯ ФАМИЛИЯ, только латиница
  purpose: string;       // пресет или своё значение, необязательно
  country: string;       // необязательно
  address: string;       // необязательно
  postalCode: string;    // необязательно
  imagePreset: CardImagePreset;
  imageAttachmentId: string | null; // зашифрованная картинка
  createdAt: string;
  updatedAt: string;
};
```

Обязательные поля: номер, срок, CVV, владелец. Остальные — по желанию.
Номер хранится без пробелов, отображается группами по 4. Срок проверяется
как `MM/YY` с месяцем 01–12. CVV — 3–4 цифры. Владелец приводится к верхнему
регистру и проверяется на латиницу, пробелы, дефис и апостроф; должно быть
минимум два слова.

Пресеты назначения: «Основная», «Для подписок», «Накопительная»,
«Кредитная», «Дебетовая». Можно ввести своё значение.

Пресеты картинки — шесть абстрактных материалов (изумруд, графит, полночь,
вино, песок, медь) на CSS-градиентах с тонкой текстурой. По умолчанию —
изумруд. Своя картинка загружается как обычное вложение (PNG/JPEG/WebP,
до 10 МБ), шифруется и хранится blob-ом; при наличии своей картинки пресет
остаётся запасным.

### Документ

```ts
type DocumentKind = "passport" | "snils" | "driver-license";
type PassportKind = "main" | "foreign";

type VaultDocument = {
  id: string;
  schemaVersion: number;
  kind: DocumentKind;
  passportKind: PassportKind | null; // только для kind = "passport"
  fullName: string;                  // ФИО, необязательно для паспорта/СНИЛС
  series: string;
  number: string;
  issuedBy: string;
  departmentCode: string;
  issuedAt: string;                  // YYYY-MM-DD
  registrationAddress: string;
  validUntil: string;                // YYYY-MM-DD, водительские права
  categories: string;                // A, B, C, BE, ...
  birthDate: string;                 // YYYY-MM-DD
  birthPlace: string;
  attachmentIds: string[];
  createdAt: string;
  updatedAt: string;
};
```

Правила по типам и обязательные поля:

| Тип | Обязательно | Необязательно |
| --- | --- | --- |
| Паспорт, основной | серия (4 цифры), номер (6 цифр), кем выдан, код подразделения (`XXX-XXX`), дата выдачи, адрес прописки | ФИО |
| Паспорт, загранпаспорт | серия (2 цифры), номер (7 цифр), кем выдан, дата выдачи | код подразделения, адрес прописки, ФИО |
| СНИЛС | номер (11 цифр) | ФИО |
| Водительское удостоверение | серия, номер, кем выдано, дата выдачи, действует до, категории, ФИО | дата рождения, место рождения, адрес регистрации, код подразделения |

Номер документа — единое поле `number` для всех типов; отдельного `snils`
нет, чтобы не было двух источников истины. СНИЛС форматируется как
`XXX-XXX-XXX YY`, номер паспорта/ВУ — по правилам своего типа.

Для водительского удостоверения `issuedBy` — текст «кем выдано»
(подразделение Госавтоинспекции), `departmentCode` — необязательный код
подразделения. Категории — строка с пресетами (A, B, C, D, BE, CE, DE и
т. п.); пользователь может ввести своё. Фото и подпись остаются в
скане-вложении.

Все даты вводятся нативным `input[type=date]`; дата выдачи не может быть
позже сегодняшней, дата окончания действия — раньше даты выдачи.
Просроченные документы не блокируются, но в детали показывается спокойная
пометка «срок истёк».

### Названия и идентификация

Отдельного пользовательского «названия» у карты и документа нет — его
не было в запросе, и лишнее обязательное поле только мешает.

- Карта: подпись для списка, поиска и подтверждения удаления собирается
  из назначения и последних четырёх цифр: «Основная · 1234», а если
  назначение пустое — «Банковская карта · 1234». Поиск идёт по владельцу,
  последним четырём цифрам, назначению, стране и адресу.
- Документ: заголовок берётся из типа — «Паспорт РФ», «Загранпаспорт»,
  «СНИЛС», «Водительское удостоверение». Вторая строка — замаскированный
  номер. Поиск идёт по заголовку, номеру, ФИО и «кем выдан». Удаление
  подтверждается заголовком и последними цифрами номера.

### Схема хранилища

- Rust: `VaultData.bank_cards: Vec<BankCard>`, `VaultData.documents:
  Vec<VaultDocument>`, оба с `#[serde(default)]`; новые структуры с
  `rename_all = "camelCase"`.
- TypeScript: `VaultData.bankCards: BankCard[]`, `VaultData.documents:
  VaultDocument[]`. Именно `bankCards`: Rust сериализует `bank_cards` как
  `bankCards`, и это единственное каноническое имя в файле.
- `empty_vault_data` и все тестовые фикстуры получают пустые массивы.
- Версия формата файла не меняется. `schemaVersion` карты/документа = 1
  для будущих миграций.
- `kind`, `passportKind` и `imagePreset` в Rust хранятся строками, а не
  закрытыми enum-ами: это позволяет открывать vault, созданный более
  новой версией, и не терять неизвестный тип. TS-слой проверяет union.

### Попутное исправление настроек

Сейчас Rust `VaultSettings` не содержит `autoLock` и `cardLayout`, поэтому
при каждом `vault_save` эти два поля молча теряются, а UI после
перезагрузки откатывается к 5 минутам и списку. Для карт/документов это
критично: тот же механизм потерял бы и новые массивы, если их не добавить
в Rust. В рамках этой работы:

- добавить `auto_lock: Option<String>` и `card_layout: Option<String>` в
  Rust `VaultSettings` с `serde(default)`;
- добавить `bank_cards` и `documents` в `VaultData`;
- добавить тест roundtrip, который проверяет, что настройки, карта и
  документ переживают сохранение и повторное чтение.

## Интерфейс

### Навигация

Слева: «Записи», «Карты», «Документы», «TOTP», «SSH», «Обмен», «Генератор»,
«Проверка», «Настройки». Иконки — `KeyRound`, `CreditCard`, `IdCard`.

На Android нижняя навигация остаётся прежней; «Карты» и «Документы» попадают
в лист «Ещё». Это не ломает привычные четыре основные кнопки.

### Раздел «Карты»

Сетка реалистичных карт: 2 колонки на широком экране, 1 на телефоне.
Пропорции 85.6 × 54 мм (1.586:1), максимум ~420 px. Сверху поиск и кнопка
«Добавить карту». Пустое состояние объясняет, что здесь появятся карты.

Лицевая сторона:

- картинка пользователя или выбранный пресет, затемняющий градиент снизу
  для читаемости;
- вверху слева — выделенная плашка назначения («Основная», «Для подписок»
  или своё значение), если оно заполнено;
- внизу справа — номер карты, под ним имя владельца. Номер в списке
  маскируется до последних четырёх цифр; полный номер — в детали;
- никакого ховер-свечения; карточка остаётся спокойной.

Детальный просмотр — модальное окно:

- вверху крупный эскиз карты;
- клик/Enter/Space переворачивает карту на 180° по Y с 3D-анимацией;
- на обороте: тёмный слой поверх картинки, тонкая магнитная полоса,
  слева по центру — срок, справа по центру — CVV; назначения, номера и
  имени на обороте нет;
- под картой — компактный блок «Данные»: номер и владелец видны сразу,
  срок и CVV появляются только после переворота (до этого — «На обороте»);
  далее назначение, страна, адрес, индекс; пустые необязательные поля не
  показываются;
- копирование номера и CVV с автоочисткой буфера; кнопка CVV доступна
  только в перевёрнутом состоянии;
- «Редактировать», «Удалить», дата изменения.

Анимация уважает `prefers-reduced-motion`; при reduced motion карта
переключается без вращения. У карты есть подпись «Нажмите, чтобы
перевернуть» под эскизом.

### Редактор карты

Модальное окно:

1. Выбор оформления: шесть пресетов, кнопка «Загрузить картинку» и
   «Убрать картинку». Превью выбранного варианта.
2. Обязательные поля: номер, срок, CVV, владелец.
3. Необязательные: назначение (пресеты + «Своё»), страна, адрес, индекс.
4. Сохранение/отмена, ошибки по полям.

CVV в форме скрыт как пароль с кнопкой «Показать». Номер форматируется
на лету. Владелец автоматически переводится в верхний регистр.

### Раздел «Документы»

Сетка карточек-документов: 2 колонки на широком экране, 1 на телефоне.
Вверху поиск и «Добавить документ». Карточка содержит цветную плашку типа
вверху слева (как у банковской карты), название, замаскированный номер и
счётчик вложений. Это не пластиковая карта, а спокойная «папка документа».

Детальный просмотр:

- плашка типа, поля документа, вложения с превью/скачиванием;
- «Редактировать», «Удалить», дата изменения;
- копирование серии/номера/СНИЛС.

### Редактор документа

Сначала выбор типа: «Паспорт», «СНИЛС», «Водительское удостоверение».
Для паспорта — переключатель «Основной / Загранпаспорт». Поля меняются по
типу. Внизу — общий `AttachmentPicker` для сканов. Сохранение/отмена,
ошибки по полям.

### Мобильная версия

Те же экраны; сетки в одну колонку, модальные окна на всю ширину,
кнопки в футере столбиком. Android back закрывает деталь/редактор, затем
возвращает в «Записи».

## Вложения и картинки

- Картинка карты: отдельное зашифрованное вложение, ссылка
  `imageAttachmentId`. Ограничение 10 МБ, PNG/JPEG/WebP. SVG и GIF не
  принимаются.
- Документы: существующий `AttachmentPicker` и blob-хранилище, любые
  файлы до общего лимита 50 МБ.
- Для показа картинки карты — хук, который расшифровывает blob и создаёт
  object URL; URL освобождается при размонтировании.
- Осиротевшие вложения не удаляются автоматически (как и сейчас у записей).

## Безопасность

- Номер, срок, CVV, владелец и поля документов лежат в зашифрованном
  `pms.vault`; картинка — в зашифрованном blob-е.
- В списке карт номер маскируется; полный номер виден в детали, CVV и
  срок — только после переворота, в том числе в текстовом блоке «Данные».
- Копирование номера/CVV идёт через существующий `copySecret` с очисткой
  буфера; копирование CVV доступно только после переворота.
- Вложения документов не расшифровываются до открытия превью.
- Никаких сетевых запросов для карт/документов.

## Совместимость и миграция

- Старые vault-файлы открываются без изменений: новые массивы пустые.
- `.pmsvault`, бэкапы и передача между устройствами уже включают весь
  `pms.vault`, поэтому карты/документы переносятся автоматически.
- Rust и TS модели обновляются синхронно. Все поля карт/документов и
  настройки `autoLock`/`cardLayout` явно добавлены в Rust, иначе
  `vault_save` выбросил бы их при повторной сериализации.

## Проверки

- Rust: serde roundtrip `VaultData` с картой, документом и настройками
  `autoLock`/`cardLayout`; десериализация старого payload без новых полей;
  `empty_vault_data`.
- TS unit: форматирование номера, маска, срок, CVV, владелец, валидация
  паспорта/СНИЛС/ВУ, пресеты.
- Компонентные: переворот карты (front/back, CVV/срок), редактор карты,
  динамические поля документа, вложения.
- E2E: создать карту с пресетом, открыть, перевернуть, увидеть CVV; создать
  паспорт с плашкой «Основной», СНИЛС и ВУ; прикрепить файл; отредактировать
  и удалить; проверить мобильную навигацию.
- Сборка macOS + Android, визуальная проверка карт и документов.

## Решения, которые я предлагаю

1. В списке карт номер маскируется до последних четырёх цифр; полный номер
   показывается в детали. Это безопаснее и не мешает «настоящему» виду.
2. На самой карте вверху слева показывается только назначение; страна,
   адрес и индекс — в полях детали. Иначе карта превращается в таблицу.
3. Имя владельца выводится в формате «ИМЯ ФАМИЛИЯ», как просил, а не
   «ФАМИЛИЯ ИМЯ».
4. Для водительского удостоверения добавляются поля, которые реально
   печатаются в РФ: серия/номер, даты, орган выдачи, категории, ФИО,
   дата/место рождения, адрес регистрации. Фото и подпись — во вложении.
5. Карты и документы не попадают в QR-обмен и «Проверку» в этой итерации.
