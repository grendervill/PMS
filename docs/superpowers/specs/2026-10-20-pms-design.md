# PMS — локальный менеджер паролей и секретов

Дата: 2026-10-20
Статус: проект дизайна, ожидает подтверждения
Рабочее название: **PMS** (личный менеджер секретов; название можно поменять без влияния на архитектуру)

## 1. Суть

PMS — локальное приложение для хранения паролей, TOTP-секретов, SSH-ключей и вложений в одном переносимом зашифрованном хранилище. Приложение не имеет своего сервера, не отправляет телеметрию и не требует аккаунта. Пользователь сам выбирает папку хранилища и сам переносит её между устройствами.

Ключевая идея: **папка хранилища — это и есть вся программа**. Скопировал папку на другое устройство, ввёл пароль-фразу или выбрал ключ-файл — получил те же данные. Никакой привязки к конкретному компьютеру или телефону.

## 2. Цели

- Работать на macOS (Apple Silicon), Windows, Linux и Android.
- Хранить все данные только в зашифрованном виде.
- Быть лёгким, быстрым и приятным: мгновенные переходы, короткие анимации, никаких тяжёлых фреймворков поверх.
- Давать полный цикл работы с записями: создание, просмотр, редактирование, копирование, история, вложения, комментарии, URL.
- Поддерживать TOTP-коды, SSH-ключи, генераторы логинов и паролей.
- Предупреждать о слабых и повторяющихся паролях, но не мешать пользователю сохранить то, что он хочет.
- Легко расширяться новыми типами записей и разделами.

## 3. Не-цели v1

Это сознательно не делаем в первой версии, чтобы не утонуть:

- собственный сервер синхронизации, облако, аккаунты;
- браузерное расширение и автозаполнение;
- iOS и Intel Mac;
- совместная работа и общие хранилища для команды;
- WebAuthn, аппаратные ключи, биометрия;
- восстановление доступа, если потеряны и пароль-фраза, и ключ-файл;
- импорт из Bitwarden/1Password/KeePass;
- сканирование QR для TOTP;
- формат PuTTY PPK;
- SSH-agent;
- банковские карты, документы, произвольные типы записей;
- встроенная синхронизация и автоматическое слияние конфликтов.

Часть из этого заложена точками расширения, но не реализуется сейчас.

## 4. Анти-цели

Проект считается неудачным, если:

- данные уходят в сеть без явного действия пользователя (кроме загрузки иконки сайта, которую можно отключить);
- потеря пароль-фразы или ключ-файла оставляет хоть какую-то лазейку;
- приложение становится тяжёлым: долгий старт, лаги при открытии карточек, гигантский установщик;
- обновление или переезд на новое устройство может незаметно перезаписать чужое хранилище;
- интерфейс требует чтения документации, чтобы просто добавить запись;
- красивый, но хрупкий: падение при неожиданном файле, битом заголовке или отключённом диске.

## 5. Решения пользователя

| Вопрос | Решение |
|---|---|
| Стек | Tauri 2 + React + Rust |
| Android и папка | SAF: пользователь выбирает папку через системный диалог |
| Синхронизация | Вручную: копирование папки или экспорт/импорт |
| Вход по ключу | Пароль-фраза **или** ключ-файл (альтернативные способы) |
| Форматы SSH | OpenSSH + PEM/PKCS#8 |
| SSH-записи | Отдельный раздел + привязка ключей к обычным записям |
| TOTP | Поле в карточке + общий экран всех кодов |
| Вложения | Любые файлы; превью для изображений, PDF и текста; лимит 50 МБ по умолчанию |
| Генератор логинов | Случайная строка, по умолчанию 12 символов |

## 6. Платформы и стек

- **UI:** React 19 + TypeScript + Vite.
- **Стили:** Tailwind CSS v4 + CSS-переменные дизайн-токенов.
- **Компоненты:** Radix UI primitives (доступность, фокус, порталы) + собственные стили.
- **Иконки:** Lucide, один набор на весь проект.
- **Анимации:** Motion (Framer Motion) с поддержкой `prefers-reduced-motion`; длительности 120–220 мс.
- **Состояние:** Zustand; никакого серверного кэша, данные локальные.
- **Ядро:** Rust, Tauri 2.
- **Криптография:** `argon2`, `chacha20poly1305`, `aes-gcm`, `hkdf`, `sha2`, `zeroize`, `getrandom`, `subtle`.
- **TOTP:** RFC 6238 на Rust (`totp-rs` или собственный тонкий слой).
- **SSH:** `ssh-key`, `rsa`, `p256`, `p384`, `p521`.
- **Сеть:** только `reqwest` (rustls) для загрузки favicon; всё остальное офлайн.
- **Файлы:** Tauri fs/dialog на десктопе; собственный `tauri-plugin-saf` на Android.
- **Тесты:** Rust unit/integration, Vitest + Testing Library, Playwright.

Почему Tauri: системный WebView даёт самый маленький и быстрый десктопный бинарник, Rust-ядро естественно держит ключи и криптографию, а один React-интерфейс работает на всех платформах. Android-часть сложнее, чем у Flutter, но SAF-плагин решает задачу один раз.

### 7.2. Слои

1. **Хранилище (storage adapter).** Абстракция над папкой:
   - `pickVaultFolder()`
   - `readVault()`
   - `writeVaultAtomic(bytes)`
   - `readBlob(id)` / `writeBlob(id, bytes)` / `deleteBlob(id)`
   - `writeBackup(bytes, name)` / `listBackups()`
   - `statVault()` (mtime + SHA-256)
   - `lock()` / `unlock()` / `heartbeat()`

   Реализации:
   - `DesktopStorage` — Tauri fs + dialog.
   - `AndroidSafStorage` — Kotlin-плагин поверх `DocumentFile`/`DocumentsContract`.

2. **Крипто-ядро (Rust).** Чистые функции + сессия:
   - `vault_create(config, secret) -> header_bytes`
   - `vault_unlock(header_bytes, secret) -> { session_id, payload_json }`
   - `vault_save(session_id, payload_json) -> encrypted_bytes`
   - `vault_lock(session_id)`
   - `vault_change_passphrase(session_id, new_secret) -> updated_header`
   - `attachment_seal(session_id, attachment_id, bytes) -> blob`
   - `attachment_open(session_id, attachment_id, blob) -> bytes`
   - `generate_password(options)` / `generate_login(options)`
   - `totp_code(secret, params, unix_time)`
   - `ssh_generate(options)` / `ssh_parse` / `ssh_encrypt`
   - `favicon_fetch(url) -> bytes + mime`

3. **UI.** Feature-модули, Zustand-стор `vaultStore`, `uiStore`, `toastStore`. Роутинг лёгкий: `welcome`, `unlock`, `entries`, `entry/:id`, `totp`, `ssh`, `ssh/:id`, `generator`, `audit`, `settings`.

### 7.3. Границы и IPC

- Все секреты (пароль-фраза, ключ-файл, приватные ключи) передаются в Rust только по необходимости и не логируются.
- Rust хранит `VaultSession { vault_key: Zeroizing<[u8;32]>, vault_id, opened_at }` в `Mutex<HashMap<SessionId, VaultSession>>`; одновременно одна активная сессия.
- `vault_unlock` возвращает расшифрованный JSON. Это компромисс: UI всё равно должен показывать данные. Ключ шифрования в JS не попадает.
- На lock Rust затирает ключ, JS очищает стор и Blob URL.
- Tauri capabilities: только нужные плагины; строгий CSP; никакого удалённого кода; внешние ссылки — через opener с подтверждением.
- На Android Kotlin-плагин не видит ключи: он работает только с зашифрованными байтами.

### 7.4. Android SAF

Плагин `tauri-plugin-saf` предоставляет JS-команды:

- `pickDirectory()` — `ACTION_OPEN_DOCUMENT_TREE` + `takePersistableUriPermission`.
- `readFile(uri)` / `readFileAt(treeUri, relativePath)`.
- `writeFileAtomic(uri, bytes)` — временный документ + rename; если провайдер не поддерживает rename, запись с предварительной резервной копией и явное предупреждение.
- `listFiles(treeUri, relativePath)`.
- `createDirectory`, `deleteFile`, `stat`.
- `pickFile()` / `saveFile(suggestedName, mime)` — для ключ-файлов, вложений и экспорта.

UI-слой выбирает `DesktopStorage` или `AndroidSafStorage` по `platform()`. Остальной код от этого не зависит.

**Риск:** SAF-провайдеры (Google Drive, Dropbox) ведут себя по-разному. Атомарная запись и rename могут не поддерживаться. План: тестировать на локальном хранилище и Google Drive; при неудаче — писать во временный файл и явно показывать предупреждение о возможном конфликте. Это не блокирует v1, но требует ручной проверки.

## 8. Формат хранилища

Папка, выбранная пользователем:

```
<vault-folder>/
  pms.vault                 # заголовок + зашифрованные данные
  attachments/
    <random-id>.pmsa        # зашифрованные вложения
  backups/
    pms-YYYYMMDD-HHMMSS.vault
  pms.lock                  # пока хранилище открыто; не секрет
```

Дополнительно программа умеет собирать всё в один архив `.pmsvault` (zip с уже зашифрованными файлами) для ручного переноса. Архив не добавляет шифрования: внутри те же зашифрованные байты.

### 8.1. Заголовок `pms.vault`

```
magic: "PMSV1"
header_len: u32
header: JSON
payload: version u8 || salt[32] || nonce[24|12] || ciphertext || tag
```

Заголовок (не секрет, но целостность важна):

```json
{
  "format": 1,
  "vaultId": "uuid",
  "createdAt": "2026-10-20T...",
  "cipher": "xchacha20-poly1305" | "aes-256-gcm",
  "kdfSlots": [
    {
      "id": "uuid",
      "kind": "passphrase" | "keyfile",
      "kdf": { "algo": "argon2id", "mKiB": 65536, "t": 3, "p": 4, "salt": "base64" },
      "wrap": { "nonce": "base64", "ciphertext": "base64" }
    }
  ]
}
```

- Полезная нагрузка — JSON `VaultData`, зашифрованный ключом хранилища.
- **AAD полезной нагрузки — не сырой JSON заголовка, а каноническое неизменяемое ядро:** magic, `format`, `vaultId`, `cipher`, `createdAt`. Оно сериализуется фиксированным бинарным форматом, поэтому порядок ключей JSON не важен.
- Слоты KDF аутентифицируются отдельно: AAD обёртки = `vaultId || slotId || kind || kdf-параметры`. Подмена, перестановка или удаление слота обнаруживаются при разворачивании ключа; подделать новый слот без `vaultKey` нельзя.
- Смена пароля/ключа или KDF-профиля меняет только слоты и не инвалидирует полезную нагрузку. Смена `cipher` или `vaultId` требует перешифрования.
- `vaultId` защищает от случайного открытия не того файла; он же попадает в AAD вложений.
- Заголовок не содержит имени хранилища, логинов, URL и названий файлов — только служебные параметры и примерный размер.

### 8.2. Ключи

- Случайный **vault key** — 32 байта из OS CSPRNG.
- **KEK** для слота = Argon2id(secret, salt, параметры слота).
- Vault key заворачивается KEK через AEAD; в слоте лежит nonce + ciphertext + tag.
- Секрет пароль-фразы: UTF-8, Unicode NFC. Пробелы в начале/конце не обрезаются; UI предупреждает о Caps Lock и невидимых символах.
- Секрет ключ-файла:
  - **произвольный файл:** `SHA-256("PMS-KEYFILE-FILE-v1" || bytes)`. Любое изменение содержимого файла (не только переименование, но и пересохранение облаком) меняет секрет и делает вход невозможным. UI прямо предупреждает: храни нетронутую копию ключ-файла.
  - **SSH-ключ:** файл парсится, при наличии парольной фразы расшифровывается; затем используется **канонический материал закрытого ключа**, а не байты файла: для Ed25519 — 32-байтовый seed, для RSA — PKCS#1 DER, для ECDSA — приватный скаляр фиксированной длины. Домен: `SHA-256("PMS-KEYFILE-SSH-v1" || type || material)`. Поэтому смена парольной фразы ключа, комментария, формата OpenSSH/PEM/PKCS#8 или пересохранение файла не ломают вход.
  - Публичный ключ вместо приватного отклоняется с понятной ошибкой.
- Приложение не хранит отпечаток ключ-файла: неверный файл определяется неудачным разворачиванием ключа, а не быстрым хэшем (это не даёт офлайн-перебора). Последний путь ключ-файла может запоминаться локально для удобства, но не является доверенным.
- Слоты альтернативные: при создании можно включить пароль-фразу, ключ-файл или оба. Если включены оба, для входа достаточно любого. Это выбор пользователя; UI явно пишет, что это два независимых ключа.
- Пароль-фраза и ключ-файл не хранятся. Ключ-файл не копируется в хранилище; программа запоминает только последний путь локально (необязательно).
- Потеря всех способов входа = потеря данных. Восстановления нет.

### 8.3. Шифрование

- По умолчанию **XChaCha20-Poly1305** (24-байтовый nonce, безопасен при случайной генерации).
- Альтернатива по выбору пользователя: **AES-256-GCM** (аппаратное ускорение на устройствах с AES-NI).
- Полезная нагрузка `pms.vault`:
  - конверт: `version u8 || salt[32] || nonce[24|12] || ciphertext || tag`;
  - `payload_key = HKDF-SHA256(vault_key, salt, info="PMS vault payload v1")`;
  - nonce случайный при каждом сохранении;
  - AAD — каноническое неизменяемое ядро заголовка (см. 8.1).
  Соль лежит внутри конверта, поэтому обычное сохранение не меняет заголовок, а случайный nonce не повторяется.
- Смена пароля/ключа или KDF-профиля перезаворачивает `vaultKey` в слотах; полезная нагрузка и её AAD не меняются. Команда возвращает только новый заголовок.
- Полная смена `vaultKey` (re-key) требует перешифровать полезную нагрузку и все вложения; это отдельная операция v1.1, не обычная смена пароля.
- Вложения `.pmsa`:
  ```
  magic "PMSA1" || version u8 || cipher u8 || salt[32] || nonce[24|12]
  || original_size u64 || ciphertext || tag
  ```
  `attachment_key = HKDF-SHA256(vault_key, salt, info="PMS attachment v1")`;
  AAD = `vaultId || attachmentId || version || original_size`.
  У каждого файла свой salt/nonce. Формат v1 — цельный AEAD-блок; потоковая версия с чанками — v2.
- **Транспорт вложений в v1 — целиком через IPC, без потоковой передачи.** Tauri 2 raw IPC (`ArrayBuffer`), пик памяти ~3× размера файла. Лимит по умолчанию 50 МБ; на десктопе максимум 100 МБ, на Android — 50 МБ с предупреждением при >25 МБ. Если этого мало, v2 переходит на чанки и потоковый SAF-стрим.
- Параметры KDF хранятся в заголовке и **никогда не перезатираются** при открытии чужого хранилища. Открытие использует ровно то, что записано.
- При разборе заголовка параметры ограничиваются (m ≤ 1 ГиБ, t ≤ 10, p ≤ 8), чтобы вредоносный файл не вызвал OOM/зависание.

### 8.4. Профили KDF

| Профиль | Argon2id | Когда |
|---|---|---|
| Стандартный | 64 МиБ, t=3, p=4 | По умолчанию; быстро на телефоне |
| Усиленный | 256 МиБ, t=4, p=4 | Хороший баланс для важных хранилищ |
| Параноидальный | 512 МиБ, t=6, p=4 | Только десктоп; на Android предупреждение о памяти |

Cipher выбирается отдельно: XChaCha20-Poly1305 или AES-256-GCM. Смена профиля/пароля перезаворачивает ключ; смена cipher требует перешифрования данных (отдельная операция «перешифровать хранилище», v1.1).

### 8.5. Модель данных (расшифрованная)

```ts
type VaultData = {
  schemaVersion: 1;
  id: string;                 // совпадает с vaultId
  name: string;               // отображаемое имя хранилища
  createdAt: string;
  updatedAt: string;
  settings: VaultSettings;
  entries: Entry[];
  sshKeys: SshKey[];
  attachments: AttachmentMeta[];
  drafts: Draft[];
};

type Entry = {
  id: string;                 // UUID v4, пользователю не показывается
  kind: "login";
  schemaVersion: 1;
  name: string;               // обязательно
  login: string;
  password: string;
  url: string;
  comment: string;
  totp?: TotpConfig;
  attachmentIds: string[];
  sshKeyIds: string[];
  loginHistory: HistoryItem[];
  passwordHistory: HistoryItem[];
  createdAt: string;
  updatedAt: string;
};

type HistoryItem = {
  value: string;
  changedAt: string;
};

type TotpConfig = {
  secret: string;             // base32
  algorithm: "SHA1" | "SHA256" | "SHA512";
  digits: 6 | 8;
  period: 30 | 60;
  issuer?: string;
  account?: string;
};

type SshKey = {
  id: string;
  name: string;               // обязательно
  type: "ed25519" | "rsa" | "ecdsa";
  rsaBits?: 2048 | 3072 | 4096;
  curve?: "p256" | "p384" | "p521";
  publicKey: string;          // OpenSSH authorized_keys
  privateKey: string;         // OpenSSH private, может быть зашифрован парольной фразой
  passphrase?: string;        // если пользователь захотел хранить
  comment: string;
  attachmentIds: string[];
  createdAt: string;
  updatedAt: string;
};

type AttachmentMeta = {
  id: string;
  name: string;
  mime: string;
  size: number;
  sha256: string;
  kind: "image" | "pdf" | "text" | "other";
  createdAt: string;
};

type Draft = {
  id: string;                 // id записи или "new"
  kind: "entry" | "ssh";
  payload: unknown;           // поля формы; схема совпадает с редактором
  updatedAt: string;
};
```

- `AttachmentMeta[]` хранится в `VaultData` (в зашифрованном виде), а сами байты — в `attachments/*.pmsa`.
- Пути установленных SSH-ключей — **локальные для устройства** и не попадают в синхронизируемое хранилище. Они лежат в локальном конфиге приложения, привязанном к `vaultId` и `sshKey.id`.
- Настройки внешнего вида (тема, акцент) — локальные. Настройки безопасности (авто-lock, буфер, лимит вложений) — в `VaultSettings`, чтобы переноситься с хранилищем.
- История ограничена 50 значениями на поле; старые вытесняются.
- Черновики форм (`drafts`) хранятся в зашифрованном `VaultData`, а не в plaintext. Они создаются при авто-блокировке с несохранёнными изменениями и удаляются после восстановления или явного отказа.
- Вложения, добавленные в ещё не сохранённую форму, сразу шифруются и пишутся как staged-blob; метаданные попадают в черновик. При отмене blob остаётся сиротой до ручной очистки.

## 9. Криптографические сценарии

### 9.1. Создание хранилища

1. Пользователь выбирает папку (десктоп — диалог; Android — SAF).
2. Вводит имя хранилища, пароль-фразу и/или выбирает ключ-файл.
3. Выбирает профиль KDF и cipher.
4. Rust генерирует `vaultId`, `vaultKey`, соли, заворачивает ключ в выбранные слоты.
5. Создаются `pms.vault`, `attachments/`, `backups/`.
6. Права: `pms.vault` 600, каталоги 700 (если программа создала их сама; чужую папку не трогаем).
7. Хранилище сразу открыто; показывается пустой экран.

### 9.2. Открытие и разблокировка

- Приложение всегда просит вход: пароль-фразу, ключ-файл или оба способа, если включены.
- Пароль-фраза: поле с показать/скрыть, индикатор Caps Lock, предупреждение о раскладке.
- Ключ-файл: выбор файла; если это зашифрованный SSH-ключ — запрос его парольной фразы.
- Неверный секрет: общее сообщение «Не удалось разблокировать», без подсказок, с задержкой 1 секунда после неудачи. Argon2 сам по себе даёт задержку.
- После успеха UI получает `VaultData`, запускает таймер авто-lock.
- Если файл повреждён/обрезан — понятная ошибка и предложение восстановить из `backups/`.

### 9.3. Сохранение

- Перед записью storage-адаптер сравнивает SHA-256 текущего `pms.vault` с хэшем на момент открытия.
- Если файл изменился извне — конфликт (см. 12.3), запись блокируется.
- Иначе: копия текущего файла в `backups/`, шифрование, атомарная запись, обновление хэша.
- Вложения пишутся один раз и не перезаписываются; удаление — только после подтверждения.

### 9.4. Смена пароля/ключа

- Требуется разблокированное хранилище.
- Новый секрет заворачивает тот же `vaultKey`; данные не перешифровываются.
- Меняются только поля слотов в заголовке; AAD полезной нагрузки от слотов не зависит, поэтому старый ciphertext остаётся валидным. Команда возвращает новый заголовок, payload не трогается.
- Если включены оба способа, можно сменить один, не трогая другой.
- Нельзя удалить последний способ входа.
- Старые резервные копии остаются со старыми слотами; для их открытия может понадобиться старый пароль. UI предупреждает.

### 9.5. Безопасность памяти

- Rust: `zeroize` для ключей и секретов; `secrecy` для типов, которые нельзя случайно залогировать.
- JS: после lock очищаются стор, буферы и Blob URL; строки в JS не затираются детерминированно — это ограничение платформы, зафиксировано в модели угроз.
- Логи: никаких секретов, URL с токенами, содержимого полей. Только коды ошибок и служебные события.
- Release-сборка без devtools; CSP запрещает внешние скрипты.

## 10. Функциональность

### 10.1. Первый запуск

Экран приветствия:

- «Создать хранилище»;
- «Открыть существующее»;
- список недавних (путь/URI, имя, дата; без секретов);
- переключатель темы.

Создание — мастер из 3 шагов:

1. Папка и имя.
2. Защита: пароль-фраза + подтверждение, сила, ключ-файл (опционально), профиль KDF, cipher, предупреждение об отсутствии восстановления.
3. Проверка и создание.

Если в папке уже есть `pms.vault`, создание блокируется. Если папка не пуста, но хранилища нет — предупреждение, чужие файлы не трогаем.

### 10.2. Записи

Список:

- карточки: favicon или монограмма, имя, комментарий (если есть), домен URL, бейджи TOTP/SSH;
- поиск по имени, логину, URL, комментарию;
- сортировка: по имени / по изменению;
- пустое состояние с подсказкой.

Просмотр:

- имя, favicon, URL (открыть во внешнем браузере с подтверждением);
- логин с кнопкой копирования;
- пароль скрыт, кнопки «показать» и «копировать»;
- TOTP-код с таймером и копированием;
- комментарий;
- вложения с превью;
- привязанные SSH-ключи;
- даты создания/изменения;
- внизу: «Редактировать», «История», «Удалить».

Создание/редактирование:

- имя (обязательно), логин, пароль, URL, комментарий;
- справа от логина и пароля — отдельные кнопки генератора;
- индикатор силы пароля;
- предупреждение о повторяющемся пароле со ссылками на записи;
- блокировка повторного использования старого пароля этой записи;
- TOTP: вставить секрет или `otpauth://` URI;
- вложения: добавить/удалить, превью, лимит;
- привязка SSH-ключей;
- внизу «Сохранить» и «Отменить»; при несохранённых изменениях — подтверждение закрытия.

Удаление:

- подтверждение с именем записи;
- удаление из `VaultData`; вложения остаются сиротами до ручной очистки;
- резервная копия предыдущего состояния остаётся.

### 10.3. Генераторы

**Пароль:**

- длина 8–128, по умолчанию 16;
- переключатели: строчные, заглавные, цифры, спецсимволы;
- выбор отдельных спецсимволов (сетка) + свой набор;
- исключение похожих символов (`0O1lI|`);
- гарантия хотя бы одного символа из каждой включённой группы (если длина позволяет);
- CSPRNG, без смещения;
- кнопка «Сгенерировать» каждый раз создаёт новый пароль с текущими настройками;
- «Использовать» и «Скопировать»;
- индикатор силы (zxcvbn, лениво загружается);
- настройки запоминаются.

**Логин:**

- длина 8–64, по умолчанию 12;
- наборы: строчные + цифры по умолчанию; можно добавить заглавные, символы, точку/дефис;
- исключение похожих;
- отдельные настройки от пароля;
- «Сгенерировать» пересоздаёт, «Использовать» подставляет.

Поля по умолчанию пустые: генератор — помощник, а не обязательный шаг.

### 10.4. Сила и повторное использование

- Сила считается локально через zxcvbn; оценки 0–4, подписи «очень слабый … очень надёжный».
- Слабый пароль: предупреждение, сохранение разрешено.
- Повторяющийся пароль: предупреждение со списком других записей; сохранение разрешено.
- Старый пароль этой записи: сохранение **блокируется** с сообщением, в какой истории он уже был.
- Экран «Проверка»: группы повторяющихся паролей, слабые пароли, записи без TOTP (информационно). Клик ведёт к записи. Никаких сетевых проверок утечек.

### 10.5. История

- При изменении логина или пароля старое значение попадает в историю с датой.
- История показывается в модальном окне: список, маска, «показать», «копировать».
- Старый пароль нельзя применить повторно; для логина допускается «подставить» (логины могут повторяться).
- Лимит 50 значений на поле.

### 10.6. TOTP

- Секрет base32 или `otpauth://totp/...`; алгоритм, цифры, период.
- Код обновляется каждую секунду; кольцо/полоса обратного отсчёта; копирование.
- Секрет скрыт, показывается по кнопке.
- Общий экран: все записи с TOTP, поиск, живые коды, копирование.
- Часы берутся системные; при сильном расхождении — предупреждение.

### 10.7. SSH

Раздел SSH:

- список ключей: имя, тип, fingerprint SHA-256, число привязанных записей;
- создание: имя, тип (ed25519/RSA/ECDSA), размер/кривая, комментарий, парольная фраза (опционально), кнопка «Сгенерировать»;
- генерация в Rust; RSA 4096 может занять секунды — индикатор прогресса;
- просмотр: публичный ключ, приватный скрыт, парольная фраза скрыта, привязанные записи, вложения;
- копирование публичного/приватного ключа, показ приватного с предупреждением;
- «Установить в ~/.ssh» (десктоп): выбор папки, имя файла, запись private 600 / public 644, создание каталога 700;
- Windows: ACL через `icacls`, только текущий пользователь;
- Android: «Экспортировать» через SAF (понятия POSIX-прав нет);
- «Проверить права»: показывает статус, чинит chmod/ACL; если владелец другой — показывает готовую команду `sudo chown ...` для копирования, сам sudo не запускает;
- при открытии хранилища на новом устройстве — баннер «Установить SSH-ключи на это устройство» со списком; после установки проверка прав;
- привязка: в редакторе записи мультивыбор ключей; в карточке ключа — список использующих его записей;
- форматы экспорта: OpenSSH private/public, PEM PKCS#1 (RSA), SEC1 (ECDSA), PKCS#8; публичный — OpenSSH.

История версий SSH-ключей в v1 не ведётся: ротация — это новый ключ. Старый можно сохранить как отдельную запись. (Точка расширения.)

### 10.8. Вложения

- Любой тип файла; лимит 50 МБ на файл по умолчанию (1–100 МБ на десктопе, 1–50 МБ на Android; при >25 МБ на Android — предупреждение о памяти).
- В v1 файл передаётся целиком через raw IPC и шифруется как один AEAD-блок; пик памяти ~3× размера файла. Потоковые чанки — v2.
- Превью: изображения (кроме SVG), текст (UTF-8, до 1 МБ), PDF — встроенный просмотрщик WebView, где поддерживается; иначе «Скачать/Открыть». Blob URL отзывается при закрытии и блокировке.
- Имена файлов и MIME хранятся только в зашифрованных метаданных.
- Экспорт расшифрованного файла — только по явному действию, с предупреждением.
- Удаление: подтверждение; blob **не удаляется автоматически**. «Очистить неиспользуемые вложения» — ручная операция с предупреждением, что старые резервные копии могут потерять вложения. Автоматической чистки по возрасту нет.

### 10.9. URL и favicon

- При сохранении URL программа пытается загрузить иконку напрямую с сайта (`/favicon.ico`, затем `<link rel="icon">`), без сторонних сервисов.
- Таймаут 5 с, лимит 64 КБ, только http/https, только публичные адреса (защита от SSRF), без cookie.
- Иконка хранится в зашифрованном виде (data URL в записи), максимум 64 КБ; при неудаче — монограмма.
- Настройка «Загружать иконки сайтов» по умолчанию включена; при выключении сеть не используется вообще.
- Приватность: прямой запрос раскрывает сайту IP и факт открытия записи; это описано в настройках.

### 10.10. Копирование и буфер

- Кнопки копирования у логина, пароля, TOTP, публичного/приватного SSH-ключа.
- Тост «Скопировано. Очистка через 30 с».
- Через 30 с (настройка 15–120 с) буфер очищается, если его содержимое не изменил пользователь.
- Ограничение честно описано: история буфера ОС может сохранить значение; приложение не может это гарантировать.

### 10.11. Автоблокировка

- По умолчанию 5 минут бездействия; настройки 1/5/15/30/никогда.
- Блокировка при засыпании/выключении экрана (десктоп) и при уходе в фон (Android, через 60 с; настройка).
- При активном системном диалоге (выбор файла/папки) таймер приостанавливается.
- Ручная кнопка «Заблокировать» всегда доступна.
- **Несохранённые изменения не теряются.** При ручной блокировке с грязной формой — диалог «Сохранить черновик и заблокировать / Отменить / Заблокировать без сохранения». При авто-блокировке или засыпании форма тихо сериализуется в зашифрованный `drafts`, затем ключ затирается. После следующего входа — предложение восстановить или удалить черновик. Если сохранить черновик не удалось (диск/права), ручная блокировка отменяется и показывается ошибка; при засыпании — best effort, UI предупреждает.
- Вложения, добавленные в грязную форму, к этому моменту уже зашифрованы как staged-blob, поэтому черновик их не теряет.

### 10.12. Настройки

- **Хранилище:** путь/URI, имя, размер, экспорт/импорт `.pmsvault`, резервные копии, восстановление, ручная очистка неиспользуемых вложений.
- **Безопасность:** сменить пароль-фразу, добавить/убрать ключ-файл, профиль KDF, cipher (с перешифрованием — v1.1), авто-lock, буфер, favicon, число бэкапов, защита от скриншотов (Android).
- **Внешний вид:** тема (системная/тёмная/светлая), акцент, плотность, анимации.
- **О программе:** версия, лицензии, модель угроз.

## 11. Интерфейс и визуальное направление

### 11.1. Каркас

- **Десктоп:** левая панель 240 px: логотип, поиск, «Записи», «TOTP», «SSH», «Генератор», «Проверка», внизу — статус хранилища и «Заблокировать». Основная область — сетка карточек; детали открываются справа на широком экране или модально на узком.
- **Android:** нижняя навигация (Записи, TOTP, SSH, Настройки), FAB «+», полноэкранные детали, bottom sheets для генератора/истории, safe-area insets.
- **Первый запуск/вход:** отдельный спокойный экран без боковой панели.

### 11.2. Визуальный язык

- Направление: «личный сейф», а не «хакерский терминал». Тёмный графит, тёплый светлый вариант, один сдержанный акцент (глубокий бирюзово-зелёный), янтарный для предупреждений, красный только для опасных действий.
- Радиусы 10–16 px, тонкие границы, мягкие тени, без неона и градиентного шума.
- Заголовки — системный шрифт; секреты — моноширинный системный стек.
- Анимации: 120–220 мс, лёгкие пружины; появление карточек со стаггером 15 мс; модалки — scale/fade; переходы — slide/fade; уважать `prefers-reduced-motion`.
- Иконки Lucide, 20/24 px, единый stroke.
- Логотип: простая монограмма/замочная скважина; делается отдельно, не блокирует код.

### 11.3. Доступность

- Полная клавиатурная навигация, видимые focus-ring, ARIA-атрибуты, контраст AA.
- На Android — цели не меньше 44×44 px.
- Ошибки формы связаны с полями, не только цветом.
- Никаких анимаций, мешающих вводу пароля.

### 11.4. Горячие клавиши (десктоп)

- `Cmd/Ctrl+K` — поиск.
- `Cmd/Ctrl+N` — новая запись.
- `Cmd/Ctrl+L` — заблокировать.
- `Esc` — закрыть модалку/детали.
- `Cmd/Ctrl+C` на выделенном секрете — копировать (с теми же предупреждениями).

## 12. Надёжность и конфликты

### 12.1. Атомарность

- Запись во временный файл, `fsync`, rename поверх.
- На SAF — временный документ + rename; если провайдер не умеет, fallback с предупреждением.
- Перед записью — резервная копия.

### 12.2. Блокировка

- `pms.lock` с `instanceId`, hostname, pid, временем и heartbeat каждые 30 с.
- Свежий lock (<2 мин) другого экземпляра: предупреждение, предложение открыть только для чтения или принудительно.
- Просроченный lock игнорируется.
- На Android heartbeat может замирать в фоне — TTL и явная кнопка «Снять блокировку».

### 12.3. Внешние изменения (ручная синхронизация)

Перед сохранением сравнивается SHA-256 файла. Если изменился:

1. «Перезагрузить» — отбросить локальные изменения после подтверждения.
2. «Сохранить мою версию как конфликтную копию» — `pms.conflict-<timestamp>.vault`; пользователь потом открывает и переносит данные вручную.
3. «Перезаписать» — только после дополнительного подтверждения и резервной копии.

Автоматического слияния нет. UI прямо говорит: перед копированием папки закрой хранилище на другом устройстве.

### 12.4. Резервные копии

- Перед каждым сохранением — копия `pms.vault` в `backups/`.
- Хранится 20 последних (настройка).
- Восстановление: список с датой/размером, подтверждение, запись поверх с предварительной копией текущего.
- Бэкапы — такие же зашифрованные vault-файлы, со своими слотами. После смены пароля старые бэкапы могут требовать старый пароль.
- Бэкап содержит только `pms.vault`, но не blobs вложений: они общие и не дублируются. Поэтому удалять неиспользуемые blobs можно только вручную и с предупреждением, что старые бэкапы потеряют вложения. Автоматической чистки нет.

### 12.5. Ошибки

- Битый заголовок/тег: «Файл повреждён или это не хранилище PMS»; предложить бэкапы.
- Нет доступа к папке: предложить выбрать заново; не терять введённые данные.
- Нет места: показать ошибку, не оставлять частично записанный файл.
- Ошибка сети при favicon: тихо падать на монограмму, не блокировать сохранение.

### 12.6. Экспорт и импорт `.pmsvault`

**Экспорт** (входит в v1, потому что на Android копировать папку вручную неудобно):

- zip содержит `manifest.json` (format, vaultId, exportedAt, версия приложения, список файлов с SHA-256), `pms.vault` и все живые `attachments/*.pmsa`;
- `backups/` и `pms.lock` в архив не попадают;
- архив содержит только зашифрованные байты; дополнительное шифрование не добавляется;
- на Android сохраняется через SAF `ACTION_CREATE_DOCUMENT`, на десктопе — через диалог.

**Импорт:**

- пользователь выбирает архив, приложение проверяет manifest, magic, `vaultId`, контрольные суммы, защиту от path traversal и zip-bomb (лимит распаковки — 2× размера архива или 2 ГиБ, что меньше);
- распаковка — **только в новую/пустую папку или в выбранную папку без `pms.vault`**; перезапись существующего хранилища запрещена без отдельного подтверждения;
- импорт никогда не сливается с уже открытым хранилищем: текущее закрывается после подтверждения, импортированное открывается как отдельное;
- `attachments/` восстанавливаются, `backups/` не импортируются;
- после распаковки — обычный экран разблокировки; пароль/ключ проверяются только там.

## 13. Безопасность и приватность

### 13.1. Модель угроз

Защищаем:

- кражу/потерю устройства;
- копию папки хранилища (облако, флешка, чужой компьютер);
- случайное открытие чужого vault-файла;
- подмену/повреждение файла;
- утечку секретов в логи и сеть.

Не защищаем:

- вредоносное ПО, кейлоггер, root/jailbreak;
- наблюдение за разблокированным экраном;
- историю буфера обмена ОС;
- атаки по сторонним каналам на уровне ОС;
- физический доступ к разблокированному устройству;
- откат к старой валидной копии vault (rollback) без внешнего счётчика.

**Принятый компромисс:** пока хранилище разблокировано, весь расшифрованный `VaultData` (включая пароли, TOTP-секреты и приватные SSH-ключи) находится в памяти WebView. Это нужно для мгновенного поиска, аудита и отображения. Разделение на «индекс метаданных + отдельные запросы секретов» заметно усложнило бы все чтения и не спасало бы от кейлоггера/снимка экрана. При блокировке ключ в Rust затирается, а стор и Blob URL очищаются. Риск зафиксирован в модели угроз.

### 13.2. Меры

- Argon2id, AEAD, случайные nonce/соли, AAD.
- Ограничение параметров KDF при разборе.
- Никаких секретов в логах/аналитике; телеметрии нет.
- Строгий CSP, только локальные ассеты, никакого remote code.
- Favicon: только http/https, публичные IP, лимит размера/редиректов, без cookie.
- Внешние ссылки: подтверждение, только http/https.
- Превью: без HTML/SVG; текст как текст; PDF в изолированном blob-просмотрщике.
- SSH-ключи на диске: 600/700 (Unix), ACL (Windows); Android — SAF.
- Android: опциональный `FLAG_SECURE` против скриншотов.
- Зависимости: lockfiles, `cargo audit`, `cargo deny`, `npm audit`, минимальный набор.

### 13.3. Ограничения, о которых UI говорит честно

- Нет восстановления доступа.
- JS-память не затирается детерминированно.
- Буфер обмена может попасть в историю ОС.
- Копирование plaintext-вложения/SSH-ключа на диск снимает защиту с этого файла.
- Favicon-запрос раскрывает сайту факт открытия записи (можно отключить).
- Ручная синхронизация требует дисциплины: закрыть на одном устройстве, потом копировать.

## 14. Расширяемость

- `Entry` имеет `schemaVersion` и `kind` (в v1 только `login`); новые типы добавляются миграцией и отдельными feature-компонентами.
- Rust-команды сгруппированы по доменам; ядро не зависит от Tauri (тестируется отдельно).
- `VaultStorage` — интерфейс; новые бэкенды (например, WebDAV) добавляются без изменения UI.
- `CipherSuite`/`KdfProfile` — enum с реестром; новые алгоритмы не ломают старые заголовки.
- UI-секции регистрируются в навигации; генератор, TOTP, SSH — независимые feature-модули.
- i18n с самого начала: строки в словаре, русский по умолчанию, английский добавляется без переписывания.

## 15. Тестирование

### Rust

- KDF/AEAD roundtrip, неверный пароль, подмена заголовка, обрезка файла.
- Парсинг старых версий и миграции.
- Генератор: длина, наборы, отсутствие запрещённых символов, гарантии групп.
- TOTP: векторы RFC 6238 для SHA1/256/512, 6/8 цифр, периоды.
- SSH: генерация/парсинг/шифрование ed25519, RSA 2048/3072/4096, ECDSA P-256/384/521; PEM/PKCS#8; fingerprint.
- Favicon: URL-валидация, SSRF-защита, лимиты.
- Права: chmod/ACL на временных файлах (Unix/Windows CI).
- Бэкапы/восстановление/конфликт.

### Frontend

- Zustand-сторы, валидация форм, правила истории/дублей.
- Компоненты: доступность, клавиатура, reduced motion.
- Playwright: создать vault во временной папке, добавить запись, сгенерировать пароль, сохранить слабый/дубль (предупреждения), проверить блокировку старого пароля, вложения, TOTP, SSH, lock/unlock, перезапуск.

### Ручные проверки

- macOS ARM, Windows 10/11, Linux (Ubuntu), Android (локальное хранилище + Google Drive SAF).
- Установка SSH-ключа и `ssh -T git@github.com` (или локальный sshd).
- Переезд папки на другое устройство, восстановление прав.
- Копирование папки при открытом хранилище — конфликт.
- Оффлайн-запуск, отключённая сеть.

Каждый этап заканчивается рабочим срезом и визуальной проверкой, а не набором заглушек.

## 17. Критерии готовности v1

- На macOS ARM можно создать хранилище, добавить запись с логином/паролем/комментарием/URL/вложением/TOTP, закрыть и снова открыть.
- Слабый пароль и повторный пароль показывают предупреждения, но сохраняются.
- Старый пароль этой записи повторно использовать нельзя.
- История показывает старые логины/пароли и копирует их.
- Генератор логина и пароля работает отдельно, с настройками и пересозданием.
- TOTP-код совпадает с эталоном RFC.
- SSH-ключ генерируется, устанавливается с правами 600/700 и работает в ssh; на новом устройстве предлагается починить права.
- Хранилище открывается паролем-фразой или ключ-файлом; зашифрованный SSH-ключ спрашивает свою парольную фразу.
- Один и тот же SSH-ключ, сохранённый в OpenSSH и PEM/PKCS#8, открывает vault одинаково; изменение содержимого произвольного ключ-файла ожидаемо ломает вход и понятно объясняется.
- Android открывает то же хранилище через SAF, добавляет запись и вложение.
- При ручном копировании изменённого файла приложение обнаруживает конфликт и не перезаписывает молча.
- Авто-блокировка с несохранённой формой сохраняет зашифрованный черновик и предлагает его восстановить после входа.
- Импорт `.pmsvault` не перезаписывает существующее хранилище без отдельного подтверждения и не смешивается с открытым.
- Сборки: macOS ARM, Windows x64, Linux x64, Android APK. Запуск без сети (кроме favicon, если включено).

## 18. Мои решения (можно оспорить)

Это не требования пользователя, а мои инженерные вызовы; если что-то не нравится — меняем до кода.

1. **Один активный vault за раз**, список недавних; несколько одновременно не открываем.
2. **JSON внутри шифрования**, не SQLite: для личного хранилища до десятков тысяч записей этого достаточно, миграции и отладка проще, меньше зависимостей.
3. **Вложения — отдельные зашифрованные blobs**, а не внутри JSON: не раздувают базу и позволяют превью.
4. **Favicon — inline data URL** (до 64 КБ), без отдельного blob-файла.
5. **Авто-lock 5 минут**, буфер 30 секунд, бэкапы 20 штук.
6. **Лимит вложения 50 МБ** по умолчанию.
7. **История 50 значений** на поле.
8. **История SSH-ключей не ведётся** в v1; ротация = новый ключ.
9. **Пароль-фраза и ключ-файл — альтернативные слоты**, не обязательные вместе.
10. **Экспорт `.pmsvault`** (zip с зашифрованными файлами) входит в v1, потому что на Android копировать папку вручную неудобно.
11. **Никакого встроенного импорта** из других менеджеров в v1.
12. **Русский интерфейс** по умолчанию, i18n-каркас с английским словарём позже.
13. **Минимальные версии:** macOS 13+, Windows 10+, Ubuntu 22.04+ (WebKitGTK), Android 9+.
14. **Пароль-фраза минимум 8 символов** с сильным предупреждением, но без жёсткого порога силы; это личное приложение, решение за пользователем.
15. **Никакого sudo из приложения**: показываем точную команду и копируем её.
16. **AAD полезной нагрузки — неизменяемое ядро заголовка**, а слоты KDF аутентифицируются собственной обёрткой. Поэтому смена пароля/ключа не перешифровывает данные и не ломает старый ciphertext.
17. **Ключ-файл SSH канонизируется по материалу ключа**, а не по байтам файла; произвольный файл — по сырым байтам, и его изменение ломает вход (это явно написано в UI).
18. **Вложения в v1 — целиком через IPC**, без потоков; 50 МБ по умолчанию, 100 МБ максимум на десктопе, 50 МБ на Android. Чанки — v2.
19. **Разблокированная сессия держит расшифрованный vault в WebView**; это принятый компромисс ради мгновенного поиска и аудита, с очисткой при блокировке.
20. **Автоматической чистки вложений нет**: только ручная команда с предупреждением о старых бэкапах.
21. **Авто-блокировка сохраняет черновик** несохранённой формы в зашифрованном виде, а не выбрасывает изменения.
22. **Импорт `.pmsvault`** распаковывает в новую/пустую папку, не перезаписывает существующее хранилище без подтверждения и не сливается с открытым.

## 19. Что осталось решить пользователю

1. **Название и логотип.** Оставляем рабочее PMS или называем иначе? На архитектуру не влияет, переименование возможно позже.
2. **Визуальное направление.** Показать 2–3 макета: тёмный «сейф», светлый «бумага», контрастный «графит + янтарь»? Это единственный пункт, который стоит увидеть до кода UI.
3. **Подтверждение решений 16–22** — особенно вложения 50/100 МБ без потоковой передачи, черновики при авто-блокировке и отсутствие автоочистки. Если что-то не нравится, меняем до кода.

Уже решено без отдельного вопроса: экспорт `.pmsvault` включён в v1; истории SSH-ключей в v1 нет; авто-lock 5 минут, буфер 30 секунд, бэкапы 20; минимумы macOS 13+, Windows 10+, Ubuntu 22.04+, Android 9+.

## 20. Замечания независимой проверки и решения

| Замечание | Решение |
|---|---|
| Смена KDF-слота ломала AAD payload | AAD = неизменяемое ядро; слоты аутентифицируются отдельно; смена пароля меняет только заголовок |
| Не определено поведение импорта `.pmsvault` | Импорт только в новую/пустую папку, без слияния и без перезаписи без подтверждения; manifest + checksums + zip-bomb защита |
| Нестабильная производная ключ-файла | SSH-ключи канонизируются по материалу; произвольные файлы — по байтам, с явным предупреждением; отпечаток не хранится |
| Не определён формат `.pmsa` и транспорт | Формат v1 — цельный AEAD-блок; raw IPC; лимиты 50/100 МБ; чанки — v2 |
| Расшифрованный vault живёт в WebView | Принято явно, зафиксировано в модели угроз; очистка при lock |
| Автоочистка сирот ломает старые бэкапы | Автоочистки нет; только ручная команда с предупреждением |
| Авто-lock теряет несохранённые правки | Зашифрованные черновики в vault + восстановление после входа |
