# QR and TOTP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Добавить сканирование QR из файла и камеры, передачу карточки PMS по QR и TOTP-сканирование.

**Architecture:** Payload карточки кодируется/шифруется в Rust. QR-изображение генерируется в JS (`qrcode`), сканирование — `jsqr` по изображению или кадрам камеры через `getUserMedia`. Передача карточки не включает вложения и SSH.

**Tech Stack:** Rust (`flate2`, Argon2id, XChaCha20-Poly1305), React, `qrcode`, `jsqr`, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-21-biometrics-qr-import-design.md` (§6)

## Global Constraints

- QR-карточка: имя, логин, пароль, все URL, комментарий, TOTP. Без вложений/SSH.
- По умолчанию без пароля; пароль — явный выбор пользователя.
- Итоговая строка `PMSQR1:`/`PMSQR1E:` ≤ 2300 байт, ECC M, версия QR ≤ 40.
- Камера только по действию; при отсутствии/запрете остаётся изображение.
- Пароль QR не сохраняется.
- Android-камера не входит в этот план (macOS getUserMedia).

## Review Focus

- QR не влезает: понятная ошибка, данные не обрезаются.
- Неверный пароль QR: ошибка без раскрытия данных.
- Камера недоступна: вкладка объясняет и не ломает изображение.
- Сканирование TOTP заполняет алгоритм/цифры/период, не только secret.
- Переданная карточка не содержит вложений/SSH и не дублируется молча.
