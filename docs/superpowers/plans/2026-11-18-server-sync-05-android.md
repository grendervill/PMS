# PMS Server — Implementation Plan 5: Android

**Статус:** выполнен 2026-11-19. Отчёт: `docs/reports/2026-11-19-android-sync.md`.

> План писался по ходу работы и не детализировался заранее: Android-слой уже был в
> проекте, и объём выяснился при первом запуске на эмуляторе. Ниже — фактический
> состав работ, зафиксированный задним числом, чтобы нумерация планов не врала.

**Goal:** серверный режим работает на телефоне: кэш доступен Rust-командам, биометрия
несёт не только ключ сейфа, но и семя для входа на сервер, синхронизация не жжёт батарею
в фоне.

## Состав работ

1. **Грант кэша.** `<app_data>/remote` открыт в `fs_scope` как постоянный корень, ровно
   этот подкаталог — хранилище грантов и биометрический блоб рядом остаются закрытыми.
   `profile_id` валидируется (латиница, цифры, дефис), `..` отвергается.
2. **Биометрическая нагрузка версии 2** (`core/biometric_payload.rs`): `{ключ сейфа,
   семя}` с версионным байтом; версия 1 читается, мусор отвергается. Один формат для
   macOS и Android.
3. **Вход в сервер по биометрии:** семя из нагрузки → `remote_login_biometric`; блокировка
   сейфа обнуляет семя и в реестре сессий, и в состоянии приложения.
4. **Жизненный цикл:** таймер синхронизации останавливается, когда приложение ушло в фон,
   и срабатывает при возврате (`visibilitychange`).
5. **Проверка на эмуляторе** (Android 12, arm64): сборка release APK, установка через
   `adb`, ручной проход сценария.

## Что нашлось на устройстве и было исправлено

- подключение к серверу с самоподписанным сертификатом было невозможно: проверка шла без
  TOFU. Теперь сначала снимается отпечаток, потом тот же сервер проверяется с пином;
- пустой серверный аккаунт показывался ошибкой — теперь это экран приветствия;
- создать сейф в серверном режиме было нельзя: визард требовал папку. Теперь шаг
  «Сервер» пропускается, сейф пишется в кэш профиля.

## Осталось проверить на живом устройстве

Создание сейфа с пушем, биометрия (на эмуляторе отпечаток не настроен), фон и возврат.
