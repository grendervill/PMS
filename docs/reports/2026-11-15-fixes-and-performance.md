## 2. Имя карточки вертикально

### 2.1 Корневая причина

Заголовок карточки — flex-строка: слева «назад + монограмма + имя», справа ряд иконок.
Блок имени имел `min-w-0`, но не `flex-1`, а ряд иконок был `shrink-0`. При нехватке ширины
сжимался только блок имени, причём ниже min-content (`min-w-0` разрешает), и вместе с
`break-words` (`overflow-wrap: break-word`) слово начинало переноситься по одной букве.

Воспроизведение (Playwright + мок Tauri IPC), запись «кингуру»:

```
360 px: h2 width = 20 px, height = 201 px → 7 строк: к / и / н / г / у / р / у
```

На ширине ≥ 460 px дефект не проявлялся — поэтому он «жил» только на телефонах и узких окнах.

### 2.2 Исправление

```jsx
<div className="flex flex-wrap items-start justify-between gap-3">      // ряд иконок может переехать
  <div className="flex min-w-0 flex-[1_1_20rem] items-start gap-3.5">  // минимальный базис 20rem
    …
    <div className="min-w-0 flex-1">                                   // имя занимает остаток
      <h2 className="pms-display break-words …">{entry.name}</h2>
  <div className="ml-auto flex shrink-0 items-center gap-1">           // иконки: своя строка, справа
```

То же в карточке SSH-ключа, плюс заголовок SSH стал адаптивным (`text-[23px] sm:text-[27px]`).

### 2.4 Android

В проекте нет отдельного Android-интерфейса: `isAndroidPlatform()` влияет только на
системные вещи (Keystore, запрет скриншотов, кнопка «назад», SAF). Разметка, стили и
брейкпоинты общие, поэтому правка действует и на Android без отдельного кода.

Проверено на типичных телефонных ширинах (320/360/390/412/430 px) в Chromium и WebKit:
имя в одну строку, иконки на второй строке. Нижняя навигация и `env(safe-area-inset-bottom)`
не затронуты.

## 3. Импорт: прошлые пароли в «Комментарии»

Парсеры Bitwarden и 1PUX дописывали `\nСтарый пароль: …` в `comment`. Исправлено:

* `ImportedItem` получил `password_history: Vec<ImportedHistoryItem>` + `push_password_history`
  (отбрасывает пустое, повторы и текущий пароль);
* Bitwarden: `passwordHistory[].password` + `lastUsedDate`; 1PUX: `passwordHistory[].value` + `createdAt`;
* фронт (`importService.ts`) переносит это в `entry.passwordHistory` (дедуп, лимит 50) —
  видно во вкладке «История → Пароли»; «Комментарий» снова содержит только заметки,
  папку и кастомные поля.

Тесты: 3 rust-теста + 1 frontend-тест.

## 4. Аллокации и реаллокации при импорте

### 4.1 Что было не так

Импорт строил дерево `serde_json::Value`, затем копировал каждое поле в `String`,
а комментарий собирал `push_str`/`format!` — по 2–5 реаллокаций на запись.

### 4.2 Что сделано

1. **Ноль копий строк.** Разбор идёт сразу в структуры с `Cow<'a, str>`: строка остаётся
   срезом входного файла, копируется только если в JSON были escape-последовательности
   (`Text` — свой `Deserialize`, который использует `visit_borrowed_str`, когда может).
   Дерево `serde_json::Value` для этого не нужно — формат определяется «пробой» ключей
   (`ExportProbe` с `IgnoredAny`), то есть без аллокаций.
2. **Один проход вместо двух.** Команда `import_parse` возвращает не сериализованную
   структуру, а сразу JSON-байты (`tauri::ipc::Response`): парсер живёт на заимствованных
   данных, сериализация пишет их в один буфер. Фронт делает `JSON.parse` из `ArrayBuffer`.
3. **Всё, что растёт, растёт один раз.** `Vec::with_capacity` для списка записей, URL,
   истории, вложений; комментарий собирается в предразмеченный буфер.
4. **TOTP без аллокаций на проверку.** `totp::inspect` раньше делал
   `to_ascii_lowercase` + две `normalize_secret` + `decode` (4 аллокации на каждую запись
   с TOTP). Теперь: проверка префикса по байтам, нормализация одним `String`, валидация
   base32 в стековый буфер (`decode_mut`) — 1 аллокация.

Для форматов, которые нельзя читать напрямую (зашифрованный Bitwarden, 1PUX-zip, KeePass),
есть `into_owned()`: они платят копию, как раньше.

### 4.3 Результат (release, Apple Silicon, лучший из 3 прогонов)

| Записей | Аллокаций было | стало | на запись | Реаллокаций было | стало | Пик памяти было | стало | Время было | стало |
|---|---|---|---|---|---|---|---|---|---|
| 200 | 30 828 | **1 407** | 154 → 7 | 1 818 | **6** | 1.8 МБ | 0.3 МБ | 1.13 мс | 0.56 мс |
| 1 000 | 154 028 | **7 007** | 154 → 7 | 9 024 | **8** | 8.9 МБ | 1.7 МБ | 5.29 мс | 2.76 мс |
| 5 000 | 770 028 | **35 007** | 154 → 7 | 45 033 | **11** | 45.8 МБ | 8.5 МБ | 27.41 мс | 13.43 мс |
| 20 000 | 3 080 028 | **140 007** | 154 → 7 | 180 039 | **13** | 183.7 МБ | 34.2 МБ | 110.88 мс | 54.19 мс |

* аллокаций: **−95.5 %** на запись, реаллокаций: **−99.97 %** (осталось 6–13 на весь файл);
* мелкие реаллокации (≤ 32 Б, рост строк) — **0**; остались только несколько крупных
  расширений выходного буфера JSON;
* скорость импорта выросла в ~2 раза, пиковая память упала в ~5 раз.

Где остались 7 аллокаций на запись: по одному `Vec` на `uris`, `fields`, `passwordHistory`
(промежуточные векторы serde), по одному на выходные `urls` и `password_history`,
1 — на комментарий (только если есть папка/доп. поля) и 1 — на секрет TOTP.
Их можно убрать кастомными десериализаторами массивов (−3 на запись), если когда-нибудь
понадобится; на общую картину это уже не влияет.

### 4.4 Android

Ядро импорта — общий Rust-код (`core/import*.rs`), поэтому цифры те же. Для Android это
важнее, чем для десктопа: пик памяти на 20 000 записей упал со ~184 МБ до ~34 МБ,
а именно память — узкое место на телефонах.

### 4.5 Как повторить

```bash
cd src-tauri
cargo test --release --lib perf_audit -- --ignored --nocapture --test-threads=1
# точечный разбор «кто аллоцирует»:
cargo test --release --lib realloc_probe -- --ignored --nocapture --test-threads=1
```

Стенд (`core/perf_audit.rs`) считает аллокации/реаллокации/пик собственного аллокатора,
плюс отдельно измеряет AEAD, base64, SHA-256 и потенциал параллелизации
(импорт 5 000 записей: 13.5 мс в один поток → 4.1 мс в четыре, 3.3×; seal 4×8 МиБ: 3.4×).

## 5. Оформления (темы)

Темы — это только наборы токенов (`src/styles/tokens.css`), поэтому одна тема
перекрашивает и десктоп, и Android-сборку целиком. Выбор — в «Настройки → Оформление»,
хранится в `localStorage` (`pms.theme`) отдельно для каждого устройства, применяется
до первой отрисовки (нет вспышки другой темы). Для быстрого просмотра в браузере:
`http://localhost:1420/?theme=archive`.

### Как снята тема Bitwarden

Значения взяты с живого веб-приложения `https://vault.bitwarden.com` через Playwright:
computed styles кнопок, полей, ссылок, фона и CSS-переменные их дизайн-системы
(`--color-background`, `--color-primary-600`, `--color-text-main`, `--color-text-muted`,
`--color-secondary-*`, `--font-sans`, радиусы). Соответствие токенов:

| Bitwarden | PMS |
|---|---|
| `--color-background` `#FFFFFF` | `--surface` |
| `#F7F9FA` (фон страницы) | `--bg` |
| `--color-background-alt` `#F3F6F9` | `--surface-2` |
| `--color-secondary-100` `#E6E9EF` | `--surface-3` |
| границы полей `#D5DDE8`, `--color-secondary-300` `#A8B3C8` | `--border`, `--border-strong` |
| `--color-text-main` `#1B2029`, `--color-secondary-700` `#3F4B63`, `--color-text-muted` `#606D91` | `--text`, `--text-soft`, `--muted` |
| `--color-primary-600` `#175DDC`, `--color-primary-700` `#1A41AC` | `--accent`, `--accent-strong` |
| белый текст на синем | `--on-accent: #FFFFFF` |
| `--color-warning-700` `#8E4000`, `--color-danger-600` `#CB263A` | `--warning`, `--danger` |
| `--font-sans: Inter…` | встроенный Inter (latin + cyrillic), 3 сабсета woff2 |
| радиусы 12 px (кнопки/поля), 16–20 px (карточки) | `--radius-sm/md/lg` |
| `--color-shadow` `#A8B3C8` | `--shadow-float` |

Побочно: цвет текста на акцентной кнопке был захардкожен (`#08110d`) под зелёный акцент —
теперь это токен `--on-accent` (у Bitwarden белый, у «Терминала» почти чёрный и т.д.),
поэтому синяя кнопка сразу читается правильно.

## 8. Что осталось за рамками

* Модалка (`components/ui/Modal.tsx`) использует ту же связку `justify-between` + `min-w-0`
  без `flex-1`: переносов по буквам там нет, но очень длинные заголовки могут вылезать.
* Импорт CSV/KeePass по-прежнему копирует строки (форматы не позволяют заимствовать) —
  это десятки аллокаций на файл, не проблема на реальных объёмах.
* AES-256-GCM медленнее XChaCha (185 против 641 MiB/s): в `aes` 0.8 бэкенд ARMv8 включается
  только при `--cfg aes_armv8`; с ним замер дал 891 MiB/s. Это сборочная правка, её стоит
  проверить на всех целевых платформах отдельно.
