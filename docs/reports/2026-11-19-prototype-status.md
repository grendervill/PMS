# Этап: рабочий прототип серверной синхронизации

Дата: 2026-11-19
Статус: **рабочий прототип** (не релиз). Тег в git не ставится, версия в манифесте не меняется.

## Что считается рабочим

Полный путь «приложение ↔ сервер» пройден на реальных сборках, а не только в тестах:

- сервер `pms-server` собран и работает на тестовой VM (Debian 13, 2 vCPU, 2 ГиБ) по TLS
  с собственным сертификатом, systemd-юнит, fail-closed при отсутствии сертификата;
- приложение подключается к этому серверу с ноутбука и с эмулятора Android: проверка
  отпечатка ключа, регистрация, вход, квота;
- серверное хранилище живёт в локальном кэше, выбор режима запоминается;
- синхронизация: пуш после сохранения, пул по фокусу и таймеру, разрешение конфликтов
  человеком, офлайн-правки не теряются, вложения синхронизируются диффом;
- в настройках видно занятое место и состояние синхронизации.

## Что прототип, а не продукт

| Область | Ограничение |
|---|---|
| Развёртывание | вручную по `deploy/README.md`; автоматизированного образа и compose нет — это следующий план (`2026-11-18-server-sync-06-docker.md`) |
| Настройка сервера и вход | вход по логину и мастер-паролю есть; мастер настройки (выбор «сервер уже есть / развернуть», шаги развёртывания, выбор сертификата) тоже есть. Не сделано: готовый образ и compose, поэтому шаги установки — ручные команды |
| SSL-сертификат | сейчас ставится руками по `deploy/README.md`; выбор «Let's Encrypt / самоподписанный на 10 лет» с автопродлением — план `2026-11-18-server-sync-06-docker.md` |
| Android на устройстве | создание сейфа с пушем, биометрия и фон/возврат проверены частично (см. `2026-11-19-android-sync.md`) |
| Серверный вход | только пароль-фраза; ключ-файл и биометрия — после плана 5 |
| Лимиты | per-IP ограничения не делает сам сервер: это задача reverse proxy |
| Производительность | SQLite-запросы выполняются в реакторе (кроме удаления аккаунта); под нагрузкой это хвостовая задержка, не пропускная способность |
| Резервирование | бэкап сервера — ручной (`sqlite3 .backup` + `rsync`), расписания нет |
| Аутентификация | один аккаунт = один сейф, шаринга нет by design (§3 спеки) |
| Синхронизация | конфликт разрешается человеком, автоматического слияния нет by design |

## Что сознательно не делалось (и остаётся вне v1)

Поштучная синхронизация (CRDT), шаринг, серверные бэкапы, web-клиент, ACME внутри
сервера, push-уведомления, несколько хранилищ на аккаунт. Обоснования — в §3 спеки.
