# Клиент серверного режима: что сделано

Дата: 2026-11-19
План: `docs/superpowers/plans/2026-11-18-server-sync-02-client.md`
Спека: `docs/superpowers/specs/2026-11-18-server-sync-design.md` (§10, §11)

## Итог

Приложение умеет говорить с `pms-server` целиком через Rust: регистрация, вход по
мастер-ключу, приём и отправка сейфа потоком с `If-Match`, вложения, квота, удаление
аккаунта и продление сессии без повторного ввода мастер-ключа. В рендерер не уходят
ни токены, ни семя identity-ключа, ни байты сейфа сверх существующих путей.

Проверено против настоящего сервера на тестовой VM (`https://192.168.1.233:8443`,
свой сертификат, проверка по отпечатку SPKI):

```
сервер https://192.168.1.233:8443: сейф версии 1, занято 15 из 1073741824 байт
```

## Что появилось

| Файл | Содержимое |
|---|---|
| `src-tauri/src/core/remote/mod.rs` | `RemoteProfile`, `TlsPolicy`, `RemoteError` с кодами `remote_*` |
| `.../remote/tls.rs` | системные корни, pin по SPKI, явный `Insecure`, снятие отпечатка для первого подключения |
| `.../remote/identity.rs` | вывод ключа аккаунта из мастер-ключа, файл `remote-device.json`, восстановление ключа из семени |
| `.../remote/client.rs` | проба, регистрация, вход, метаданные сейфа, разбор ошибок сервера |
| `.../remote/vault.rs` | `pull_vault`/`push_vault` потоком через файл |
| `.../remote/blobs.rs` | блобы, квота, удаление аккаунта |
| `commands/remote.rs` | `remote_*` команды, реестр сессий, `remote_refresh` |

Серверные команды **не выдают** разрешения на файлы: пути из рендерера
разрешаются через `fs_scope.resolve` (папка выбрана человеком в диалоге или это
кэш приложения). Выдать грант «на лету» означало бы отдать IPC-каналу право
читать и писать любые файлы пользователя.

## Коды ошибок

`remote_bad_url`, `remote_insecure_forbidden`, `remote_tls`, `remote_unreachable`,
`remote_protocol`, `remote_conflict`, `remote_quota_exceeded`, `remote_unauthorized`,
`remote_not_found`, `remote_bad_request`, `remote_rate_limited`, `remote_server`,
`remote_storage`. Коды сервера переводятся в них один в один, конфликт версий приходит
как `remote_conflict` с метаданными сервера.

## Тесты

- `core::remote::tls` — 4 юнит-теста (политика http/https, формат отпечатка);
- `core::remote::identity` — 2 юнит-теста (стабильность device id, вывод ключа);
- `commands::remote` — 7 тестов против настоящего `pms-server` в процессе;
- `tests/remote_tls.rs` — 5 тестов (свой отпечаток, чужой, системные корни, http);
- `tests/remote_auth.rs` — 9 тестов (проба, регистрация, вход, второе устройство, ошибки);
- `tests/remote_vault.rs` — 5 тестов (поток, конфликт версий, отсутствие сейфа);
- `tests/remote_blobs.rs` — 5 тестов (круг блоба, квота, удаление аккаунта);
- `tests/remote_live.rs` — сценарий против живого сервера, `#[ignore]`, запуск по env;
- проверка целостности: подмена `vault.bin` на сервере в обход индекса отвергается по
  BLAKE3, локальная копия остаётся, временных файлов нет (два теста: стор и команды).

## Что не входит и придёт дальше

Кэш и экран выбора режима, движок синхронизации с очередью и конфликтами, раздел квоты в
настройках — планы 3–4. Android-грант для кэша и биометрический блок версии 2 — план 5.
