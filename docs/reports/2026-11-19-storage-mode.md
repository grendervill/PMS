# Режим хранения: что сделано

Дата: 2026-11-19
План: `docs/superpowers/plans/2026-11-18-server-sync-03-storage-mode.md`
Спека: `docs/superpowers/specs/2026-11-18-server-sync-design.md` (§10)

## Итог

При первом запуске приложение спрашивает, где живёт сейф, и запоминает ответ.
Серверный режим подключается к серверу по адресу и мастер-ключу, показывает
отпечаток ключа до входа и работает поверх локального кэша — без сети открывается
кэш, а не пустой экран.

| Что | Где |
|---|---|
| Режим и профили (localStorage, без секретов) | `src/lib/storage/mode.ts`, `src/features/storage/profiles.ts` |
| Каталог кэша и его границы в `fs_scope` | `commands/remote.rs::cache_dir`, `lib.rs` (setup) |
| Хранилище серверного режима | `src/lib/storage/remote.ts`, `getStorage()` |
| Экраны | `StorageModeScreen`, `ServerProfileForm` |
| Запуск по сохранённому выбору | `src/features/storage/startup.ts`, `src/app/App.tsx` |

## Проверки

- `vitest`: 342 теста (67 файлов), включая 14 новых на режим, профили, кэш, формы и запуск;
- `playwright`: 38 сценариев, включая новый `storage-mode.spec.ts` (выбор запоминается после
  перезагрузки, форма показывает отпечаток, «Сменить хранилище» возвращает выбор);
- `cargo test --workspace`: 375 тестов, включая `remote_cache` (раскладка кэша, запрет `..`
  в `profile_id`, доступ только к `app_data/remote`, но не к файлу грантов);
- скриншоты: `test-results/storage-mode-{chooser,local,server}.png`.

## Что осталось

Синхронизация по событиям, конфликты, офлайн-очередь и раздел квоты — план 4.
Ключ-файл и биометрия для серверного входа, Android-грант кэша — план 5.
