# Генератор паролей: что было, что добавлено, что осталось

Дата: 19.11.2026. Задача: «кажется, в генераторе не хватает возможностей». Ниже — разбор по рынку (Bitwarden, 1Password, KeePassXC, Proton Pass), что сделано в этом раунде и что предлагается дальше.

---

## 1. Что было (v0.3.2)

* Режимы: **пароль** (8–128 символов, группы «строчные/заглавные/цифры/символы», свой набор символов, «исключить похожие») и **логин** (8–64, те же группы, без гарантий по классам).
* Равномерная выборка через `OsRng`, по одному символу из каждой включённой группы, перемешивание в конце.
* Оценка силы — на фронтенде через `zxcvbn` (для уже введённых паролей).
* Не было: парольных фраз, минимумов по классам, показа энтропии для сгенерированного значения.

## 2. Что добавлено в этом раунде

| Возможность | Зачем | Где |
|---|---|---|
| **Парольная фраза** (diceware) | Единственный тип секрета, который реально запоминается без менеджера. Стандарт де-факто у всех конкурентов | `core/generator.rs::generate_passphrase`, режим «Парольная фраза» в `GeneratorPanel` |
| Словник **EFF large** (7776 слов, 12.925 бита/слово) | 5 слов = 64 бита, 6 = 77.5 бита — сравнимо с 12–15 символами случайного пароля, но запоминается | `src-tauri/assets/wordlists/eff_large.txt` (+ атрибуция в README) |
| Настройки фразы: число слов 3–12, 8 разделителей (в т.ч. «без разделителя»), «Заглавные буквы», «Добавить цифру» | Минимум, который есть у Bitwarden/KeePassXC; влияет и на энтропию (+log2(10) за цифру) | `PassphraseOptions` |
| **Минимум цифр / спецсимволов** | Требования сайтов («минимум 1 цифра и 1 символ») — сейчас пользователь перегенерировал вслепую | `min_digits`/`min_symbols` в `PasswordOptions`/`LoginOptions` |
| **Показ энтропии** («~78 бит») | Пользователь видит, что 5 слов ≈ 16-символьный пароль; снимает «сгенерирую-ка покороче» | `generator_entropy` + строка под значением |
| Допустимые значения проверяются на бэкенде | `min_digits + min_symbols ≤ length`, `min > 0` требует включённого набора, `words ∈ 3..=12`, разделитель из списка | `VaultError::BadParams` |

Энтропия считается детерминированно (`length × log2(размер набора)` и `words × log2(7776)`), не по `zxcvbn` — это честная оценка для *сгенерированного* значения, а не оценка «похожести на словарь».

Тесты: 27 в `core/generator.rs` (минимумы на 300 генерациях, границы, словник — ровно 7776 уникальных `[a-z-]`, энтропия ±0.01), 9 в `GeneratorPanel.test.tsx`, e2e-моки для новых команд.

## 3. Что ещё стоит добавить (предложение)

Отсортировано по соотношению «польза / стоимость».

### P1 — заметно улучшает ежедневное использование

| # | Возможность | Состояние |
|---|---|---|
| 1 | **Исключение конкретных символов** (`excludeChars`) | **сделано**: поле «Исключить символы» в режимах пароля/логина; фильтр после «похожих», опустевший набор → `EmptyCharset`, строка > 64 символов → `BadParams`, энтропия считается по фактическому пулу |
| 2 | **Пресеты длины** | **сделано**: 8/12/16/20/32/64 для пароля, 8/12/16/24/32/48/64 для логина; клик выставляет длину и перегенерирует |
| 3 | **Свой словник** для фраз (импорт txt) | **сделано**: селектор «EFF, английский (7776) / Свой, N слов» и кнопка «Импорт» в панели; файл (одно слово в строке, 2–24 символа, буквы/цифры/дефис/апостроф) валидируется в Rust, копируется в `app_data_dir/wordlists/passphrase.txt` с правами 0600, минимум 512 слов, максимум 50 000; энтропия пересчитывается по фактическому размеру списка (`words × log2(N)`). Готовый русский список в репозиторий не кладём — лицензии на diceware-списки разные, а импорт закрывает потребность |
| 4 | Числа в начале/в конце фразы на выбор | **сделано**: при включённом «Добавить цифру» появляется выбор «Где цифра: В конце / В начале» |
| 5 | **История генераций** | **сделано**: последние 20 значений в `sessionStorage`, кнопки «Копировать»/«Вернуть»/«Очистить», очищается при блокировке хранилища |

| # | Возможность | Комментарий |

| 6 | Произносимые пароли (CV-слоги: `bafokim-zurati`) | 3–4 слога дают ~14 бит/шт, легче диктуются по телефону; ниша |
| 7 | «Пин-код» (только цифры, 4–12, без повторов `1111`) | отдельный пресет, часто нужен для банкоматов/сейфов |
| 8 | Проверка пароля против словаря (`zxcvbn` уже в зависимостях) с блокировкой «слабого» пресета | сейчас `zxcvbn` используется только для индикатора; можно не давать сохранить заведомо слабый сгенерированный пароль |

## 4. Что менять не нужно

* Алгоритм `shuffle`/`choose` на `OsRng` — равномерный, без modulo-bias; гарантия «по одному символу из класса» соответствует ожиданиям пользователей.
* Словник EFF large — оптимальный компромисс «энтропия/запоминаемость»; менять на 2048-словный BIP39 (11 бит) без причины не стоит.
* Считать энтропию на бэкенде, а не в TS — одна реализация, тестируемая, и она же понадобится для P2-8.

## 5. Оценка

* P1 (5 пунктов) — **реализовано** (исключение символов, пресеты длины, история, свой словник, позиция цифры): 37 Rust-тестов генератора, 30 фронтенд-тестов панели, e2e-проверка импорта словника.
* P2 — 3–5 дней, часть требует UI в редакторе записи.
* P3 — по желанию, каждый пункт самостоятелен.

Приоритет: **P1-1, P1-2, P1-3** (исключение символов, пресеты длины, русский словник) — это то, на что пользователи жалуются чаще всего.
