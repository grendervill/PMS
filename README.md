# PMS

[![Build all platforms](https://github.com/grendervill/PMS/actions/workflows/build-all.yml/badge.svg)](https://github.com/grendervill/PMS/actions/workflows/build-all.yml)

Менеджер паролей, TOTP-секретов, SSH-ключей, банковских карт и документов.
Два режима хранения: **локальная папка** (как раньше) или **свой сервер
синхронизации** — одно хранилище открывается на всех устройствах. Ключи и
пароль-фразы не покидают устройство: сервер хранит только зашифрованные байты.

## Два режима хранения

При первом запуске приложение спрашивает, где живёт сейф, и запоминает ответ —
при следующем старте экран не появляется. Режим меняется в любой момент
(«Сменить хранилище»).

| | Локальный | Серверный |
|---|---|---|
| Где данные | выбранная папка | свой сервер + локальный кэш |
| Устройства | копируется вручную | синхронизируются сами |
| Без сети | полностью | открывается кэш, правки копятся |
| Аккаунт | нет | логин + мастер-пароль (или биометрия) |
| Бэкапы | рядом с сейфом | локальные в кэше, серверные — своей командой |

## Локальный режим

- Создание переносимого хранилища в выбранной папке и разблокировка
  пароль-фразой, ключ-файлом (OpenSSH / PEM / PKCS#8), пароль-фразой вместе
  с ключ-файлом или Touch ID / отпечатком. SSH-ключ можно использовать как
  отдельный альтернативный способ входа.
- Argon2id + XChaCha20-Poly1305 или AES-256-GCM; параметры KDF хранятся
  в заголовке и не перезатираются.
- «Всегда разблокировать при помощи биометрии»: до 5 попыток, ключ в macOS
  Keychain / Android-биометрии.
- Атомарная запись vault-файла, права 600/700; бэкапы по расписанию.
- Передача полной копии между устройствами по локальной сети (Bonjour +
  UDP-broadcast, шестизначный код).

## Серверный режим

Свой сервер на VPS или в домашней сети. Один человек — один аккаунт, сервер
обслуживает много пользователей: у каждого свой логин и своё хранилище.

**Вход.** `логин + мастер-пароль`; логин запоминается в приложении, поэтому
спрашивается только мастер-пароль или биометрия. Логин входит в вывод ключа
аккаунта: один мастер-пароль с разными логинами — разные пользователи.
Сервер хранит только публичный ключ, никаких паролей.

**Что делает синхронизация**

- отправка после сохранения (с дебаунсом), при возврате фокуса окна и раз в 5 минут;
- приём при разблокировке и по таймеру; скачанная версия применяется сразу,
  без перезапуска приложения;
- конфликт двух устройств не решается автоматически: диалог «оставить моё» /
  «взять серверное» (второе сначала кладёт локальную копию в `backups/`);
- офлайн — не ошибка: статус «офлайн», правки копятся и уезжают при возврате сети;
- вложения передаются диффом, серверные удаляются только через 30 дней тишины;
- в настройках видно «занято / свободно» цифрами и полосой, статус и кнопки
  «Синхронизировать сейчас», «Войти заново», «Отключиться», «Удалить аккаунт».

**Безопасность канала.** TLS обязателен по умолчанию: сервер не стартует без
сертификата, клиент отказывается идти по `http://` без явного разрешения.
Сертификат проверяется по отпечатку ключа (показывается при подключении) или по
публичным корням; при смене отпечатка приложение требует подтверждения.

**Что на сервере.** Запечатанный `vault.bin` и запечатанные вложения, версии,
размеры, логины и квоты (по умолчанию 1 ГиБ на аккаунт). Сервер не разбирает
содержимое и не видит ни мастер-ключ, ни открытые данные.

### Развёртывание

```bash
git clone https://github.com/grendervill/PMS && cd PMS/deploy/docker
cp .env.example .env      # домен/IP и режим TLS
docker compose up -d --build
```

- **сертификат выбирается при развёртывании**: `PMS_TLS=self-signed` — сервер
  выпускает свой сертификат на 10 лет (SAN из DNS/IP) и продлевает по cron;
  `PMS_TLS=acme` — TLS на Caddy с автоматическим Let's Encrypt;
- данные и сертификаты — в томе, конфиг монтируется (правится без пересборки);
- бэкап без остановки: `./deploy/docker/backup.sh /path/to/backups`;
- квоты и список аккаунтов: `pms-server accounts`, `pms-server quota-set`;
- руководства: `deploy/docker/README.md` (контейнер), `deploy/README.md` (systemd).

## Возможности приложения

- Записи: имя, логин, пароль, несколько URL, комментарий; скрытие/показ и копирование.
- Банковские карты: номер, срок, CVV, владелец, шесть пресетов оформления и
  зашифрованная своя картинка.
- Документы: паспорт РФ/загранпаспорт, СНИЛС, водительское удостоверение.
- Три режима отображения карточек, «Избранное» для всех типов элементов.
- TOTP: `otpauth://` или base32, живые коды с таймером, показ QR и **сканирование
  камерой телефона** (кадр заполняется целиком — прицел всегда над изображением).
- Передача карточки по QR, импорт Bitwarden / 1Password / KeePass / Kaspersky /
  браузерных CSV, экспорт и импорт зашифрованного `.pmsvault`.
- SSH-ключи: ed25519, RSA 2048/3072/4096, ECDSA P-256/P-384/P-521; установка в
  `~/.ssh` с правами 600/700.
- Зашифрованные вложения с превью, история логинов и паролей, предупреждения о
  слабых и повторяющихся паролях.
- Генераторы логина и пароля (длины, наборы символов, свои символы, словари).
- Автоблокировка, зашифрованные черновики форм, автоочистка буфера обмена,
  защита от скриншотов на Android, автозапуск, три значка приложения.
- Значки сайтов по домену (Google S2, кэш 30 дней, можно отключить).
- macOS (Apple Silicon), Windows, Linux и Android на одном React-интерфейсе.

## Что ещё не сделано

- Серверный режим проверен на macOS и на эмуляторе Android; на живых телефонах
  осталось пройти вход, биометрию и фон/возврат.
- ACME-режим (Let's Encrypt через Caddy) написан, но не проверялся без
  публичного домена.
- Локальная передача между устройствами по-прежнему экспериментальная:
  автообнаружение ненадёжно.
- Полноценная проверка Windows/Linux-сборок впереди.
- Переименование логина, шаринг между пользователями и поштучное слияние
  записей сознательно вне первой версии.

## Сборки для всех платформ

Публичный репозиторий: https://github.com/grendervill/PMS
Готовые сборки: https://github.com/grendervill/PMS/releases

Workflow `.github/workflows/build-all.yml` собирает:

- macOS arm64 — `.dmg`;
- Linux x64 — `.deb`, `.AppImage`; Linux arm64 — `.deb`;
- Windows x64 — `.msi`, NSIS `.exe`; Windows arm64 — NSIS `.exe`;
- Android arm64 — `.apk`.

Запуск: Actions → **Build all platforms** → Run workflow (укажите тег), либо пуш
тега `v*`. Desktop-сборки не подписаны, поэтому Windows SmartScreen и пакетные
менеджеры могут показать предупреждение. APK подписан релизным ключом PMS.

## Разработка

```bash
pnpm install
pnpm tauri dev
```

Проверки:

```bash
pnpm typecheck
pnpm test                       # 383 frontend-теста (Vitest)
pnpm test:e2e                   # 40 сценариев Playwright (мок Tauri IPC)
cargo test --workspace          # 394 теста, включая сервер и протокол
cargo clippy --workspace --all-targets -- -D warnings
cargo fmt --all -- --check
```

Сервер:

```bash
cargo build --profile server -p pms-server
cargo run --profile server -p pms-server -- check-config --config deploy/docker/server.toml
cargo test -p pms-server
```

Замеры и нагрузочные инструменты (примеры, не входят в релиз):

```bash
# аллокации на запрос: запросы идут прямо в роутер, без TLS
cargo run -p pms-server --release --example allocbench

# нагрузка: 200 пользователей, 50 сохранений каждый
cargo run -p pms-server --release --example loadtest -- \
  --url https://127.0.0.1:8443 --users 200 --pushes 50 --concurrency 32
cargo run -p pms-server --release --example loadtest -- \
  --url https://127.0.0.1:8443 --users 128 --duration 10 --concurrency 32 --reads
```

Мобильная сборка (нужны Android SDK/NDK и rustup-таргеты):

```bash
export ANDROID_HOME="$HOME/Library/Android/sdk"
export NDK_HOME="$ANDROID_HOME/ndk/28.2.13676358"
npx tauri android build --target aarch64 --apk
```

## Производительность сервера

Замеры на VM (Debian 13, 2 vCPU, 2 ГиБ, контейнер 384 МиБ), `fsync = batch`:

| Показатель | Значение |
|---|---|
| Запись сейфа (2 КиБ), 32 параллельно | **≈5 800 PUT/s**, p50 5 мс, p99 12 мс |
| Устойчивая нагрузка | 277 тыс. сохранений за минуту, 0 ошибок, память не растёт |
| Чтение сейфа | **≈12 700 GET/s**, p50 2 мс |
| Аллокации на запись | 96 аллокаций / 10 реаллокаций, байты не зависят от размера тела |
| Память сервиса | десятки мегабайт; предел контейнера не является узким местом |

Узкое место — диск (`fsync` на каждое сохранение) и два ядра; SIMD-инструкции
в собственном коде не нужны: TLS и BLAKE3 уже используют AES-NI/AVX2 из
библиотек. Подробности: `docs/reports/2026-11-21-load-test.md`.

## Безопасность

- Пароль-фраза и ключ-файл не хранятся; потеря всех способов входа означает
  потерю данных — восстановления нет.
- Сервер не видит ни мастер-ключ, ни ключ сейфа: аутентификация — подпись
  Ed25519, выведенная из мастер-ключа; токены живут 12 часов и отзываются.
- Секреты не пишутся в логи; токены и семена ключей обнуляются в памяти.
- Никакой телеметрии: единственный сетевой запрос вне синхронизации — значки
  сайтов, его можно отключить.
